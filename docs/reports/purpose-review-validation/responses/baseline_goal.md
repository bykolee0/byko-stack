# /root/baseline_goal

## 2026-10-19T07:03:13.207Z

목적은 **예약 취소가 확정된 뒤에는 해당 예약의 리마인더에 대한 새로운 외부 발송 요청이 시작되지 않도록 하는 것**입니다. 취소한 예약의 알림이 뒤늦게 발송되는 일을 막아야 하며, 취소 전에 대기열에 들어간 리마인더도 이 조건에 포함됩니다. 이미 외부 발송 서비스가 접수한 메시지의 회수는 제외합니다.

제공 자료에서 확인한 현재 동작은 다음과 같습니다.

- `app.py:1–3`: `cancel_booking`은 예약 상태를 `cancelled`로 저장하고 성공 응답을 반환합니다.
- `app.py:6–8`: `drain_one`은 대기열에서 항목을 꺼낸 뒤 예약 상태를 확인하지 않고 `provider.send`를 호출합니다.

따라서 제공 코드에는 취소된 예약의 새 발송 요청을 막는 동작이 없습니다. 다만 실제 장애 발생 순서나 빈도는 이 자료만으로 확인할 수 없습니다.

목적 달성을 판단할 때는 **취소 확정 시점과 발송 요청 시작 시점의 순서**가 근거가 되어야 합니다. 취소가 먼저 확정됐다면, 알림이 대기열에 남아 있든 worker가 이미 꺼냈든 이후 새 발송 요청은 없어야 합니다. 취소되지 않은 예약의 정상 리마인더 발송은 유지해야 합니다.

남은 경계는 하나입니다. **취소 전에 발송 요청을 시작했지만, 취소 확정 당시 외부 서비스가 아직 접수하지 않은 요청도 이번에 중단해야 하나요?** 이 경우는 ‘취소 이후 시작되는 새 요청’과 ‘이미 접수된 메시지’ 어느 쪽에도 명확히 포함되지 않아 별도 확인이 필요합니다.

실행 부록: `codex-spec-designer`, `byko-analyze`, `codex-review`, `byko-review-document` 및 연결된 공통 지침과 `REQUEST.md`, `README.md`, `app.py`를 읽었습니다. 요청과 코드의 정적 대조·직접 문서 검토를 수행했습니다. 독립 검토와 실행 테스트는 미실시이며, 구현 방법 결정과 파일 변경은 없습니다.
