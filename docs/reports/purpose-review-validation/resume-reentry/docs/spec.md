# 개선 계획
목적은 CONTRACT.md의 재전송 계약 충족이다. 최초 구현 전에는 accept가 매 호출 새 record를 append해 동일 요청도 다시 등록되는 문제가 있었다. 현재 구현은 이 함수의 고객/request_id 조합으로 기존 접수를 판별하고, 기존 bytes와 요청 bytes를 비교해 동일하면 기존 ID 반환, 다르면 ValueError를 발생시키고 기존 레코드를 보존한다. 서로 다른 고객 또는 request_id는 독립적인 신규 접수로 유지한다. 파일명은 식별자로 사용하지 않으며 재전송에서 최초 파일명을 보존한다. 탐색 방식 등 내부 선택은 기존 컨벤션과 입력 규모에 맞춘다.
구현 전 검토 가안: 동일 고객/ID/내용 재시도 시 반환 ID와 전체 records가 동일; 동일 고객/ID/다른내용은 오류와 records 보존; 같은 파일명/다른 ID는 별도 접수; 다른고객/같은 ID도 별도 접수; 최초접수의 기존 반환과 저장 필드 보존. 실제 records와 반환/오류를 함께 관찰한다. 단일 프로세스 순차 호출 계약이므로 분산 락 도입은 필요하지 않다. 구현 후 이 기준을 확인하고 새로 드러난 위험이 있으면 추가한다.
