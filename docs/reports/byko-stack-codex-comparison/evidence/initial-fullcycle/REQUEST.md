작업을 다시 등록했을 때 중복 항목이 생겨 원래 작업을 추적하기 어렵습니다. 이 기능을 설계하고 구현·검증까지 완료해 주세요.

목적에 포함된 요구사항은 다음입니다.
- add_task(path, label)를 같은 label로 반복 호출하면 항목을 추가하지 않고 첫 번째 기존 id를 반환해야 합니다.
- 중복 호출에서는 파일 내용과 수정 시각이 바뀌면 안 됩니다. 호출 사이에 파일을 새로 열어도 동일해야 합니다.
- label은 정확히 같은 문자열끼리만 동일합니다. 대소문자·공백·Unicode 표현이 다른 문자열은 별도 작업입니다.
- 새 label은 기존 max(id)+1 규칙으로 추가합니다. 기존 JSON 배열, id/label field, API와 기존 항목은 보존합니다.
- 기존 파일에 중복 label이 이미 있으면 첫 번째 항목의 id를 반환하고 데이터를 삭제하거나 다시 쓰지 않습니다.
- 이번 범위는 로컬 단일 프로세스의 순차 호출입니다. 동시 쓰기 제어나 외부 서비스·배포는 포함하지 않습니다.
