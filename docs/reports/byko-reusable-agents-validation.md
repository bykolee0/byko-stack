# 재사용 에이전트·스킬 작성과 검증

## 대상과 목적

`plugins/byko-stack-codex/agents/`의 분석가·구현자·검토자·뷰어 생성자와 `skills/byko-*` 여섯 개를 추가했다. 아래 최초 검증 당시 모델 기본값은 모두 `gpt-6-sol`, 노력 수준은 `high`였다. 기존 Stack의 설계·개발·리뷰 workflow와 Goal 플러그인에는 연결하지 않았다.

역할은 자신의 준비·수행·검증·반환을 책임진다. 전문 방법은 메인에서도 단독으로 사용할 수 있는 스킬에 둔다. 고정 호출 schema, 선행 스펙·manifest, 메인의 완벽한 인계를 요구하지 않는다. 실제 작업의 명시된 범위와 권한이 역할의 가능한 능력보다 우선한다.

## 형식·패키징

- 네 TOML을 Python `tomllib`으로 파싱하고 필수 필드·고유 이름·모델·노력 수준을 확인했다.
- 새 스킬 여섯 개의 `quick_validate.py`와 플러그인의 `validate_plugin.py`를 통과했다.
- UI 메타데이터, 역할이 참조하는 스킬의 존재, Markdown 상대 링크가 이 플러그인 내부에서 해석되는지 확인했다.
- 시스템 Python에 PyYAML이 없어 기존 uv cache의 PyYAML을 `PYTHONPATH`로 연결했다. 전역 설치·설정은 바꾸지 않았다.
- 기존 tracked 파일은 수정하지 않았다. 자동 native 등록, 개인 설정 변경, 플러그인 재설치·배포·commit은 수행하지 않았다.

## 독립 실행

임시 경로 `/private/tmp/byko-reusable-ry2vmg0t/`에 플러그인 사본과 fixture를 두었다. 실행자는 새 컨텍스트의 `gpt-6-sol` / `high`로 생성하고 TOML의 역할 지침 및 해당 스킬을 읽게 했다. 이는 역할 지침을 전달하는 경로의 확인이며, TOML native 등록이나 자동 선택을 검증한 것은 아니다. 이 경로의 산출물은 임시 파일이며 배포 파일에 포함되지 않는다.

| 작업 | 실제 관찰 |
|---|---|
| 분석 | 코드만 읽어 같은 label의 재등록이 새 항목·ID를 만든다고 분석했다. 제외한 data 디렉터리·외부 서비스는 조사하지 않았다고 보고했고, 지정한 Markdown 보고서만 작성했다. 코드 해석과 보고서 내용은 메인이 대조했다. |
| 구현 | 선행 스펙 없이 중복 등록의 첫 ID 반환과 파일 bytes·mtime 보존을 구현했다. 구현자의 실제 임시 파일 unittest 5개가 통과했다. 메인은 최초 등록, 파일 보존, 문자열 구분, 첫 ID 0, max ID, JSON escape, 잘못된 JSON, 파일 재개방의 외부 행동 검사 8묶음을 추가로 통과시켰다. 동시 쓰기는 범위 밖이다. |
| 코드 리뷰 | 기존 테스트 1개가 통과해도 CSV 파일에는 이메일 원문이 남는 오류를 실제 임시 CSV 재읽기로 확인했다. 메인도 같은 파일 경계에서 재현했다. 검토자는 소스를 수정하지 않았다. |
| 문서 리뷰 | 미리보기 마스킹만으로 공유 CSV의 개인정보 제거를 완료로 판정하는 설계·검증의 모순을 원래 요구사항과 대조해 지적했다. 구현 테스트 통과를 설계 타당성의 대용으로 쓰지 않았다. |
| 뷰어 제작 | 형식 지정 없는 요청에서 단일 HTML을 만들었다. 정원·대기·24시간 응답·중복 배정 금지·매일 할 일·자동 알림 제외를 설명하고 시각적 흐름·탐색·응답 예시를 제공했다. HTML·링크·외부 자산·JavaScript 구문을 검사했다. |
| 뷰어 리뷰 | 작성 맥락 없는 별도 검토자가 내용과 원문을 대조하고, 응답 선택 후 결과 문구와 대기열 강조가 서로 다른 상태를 나타내는 문제를 발견했다. 실제 브라우저 검증과 정적 검토를 구분했다. |

새 패키지 자체도 별도 컨텍스트에서 검토했다. 목적 적합성, 범위 제한, 선행 workflow 의존성, 역할과 스킬 분리, 설치·동적 생성 설명에서 중요한 공백이나 모순을 발견하지 못했다. 이는 지침에 대한 정적 검토이며 모든 작업에서의 성공을 뜻하지 않는다.

## 발견한 문제와 보완

뷰어 예제의 선택 상태 불일치를 바탕으로 제작 스킬에 가능한 선택별 설명·시각 자료·선택 표시의 일관성을 확인하도록 보완했다. 정적인 순서도와 현재 상태를 구별한다는 원칙으로 작성했으며, 해당 예제의 특정 UI나 도메인을 고정 규칙으로 만들지 않았다.

작성자가 예제를 수정했고, 같은 독립 검토자가 해당 finding의 해소와 관련된 새 모순 부재를 정적 소스에서 확인했다. 메인도 실제 inline handler를 Node DOM mock으로 실행해 수락·거절·무응답·수락 복귀에서 문구·대기열·선택·접근성 표시의 일치를 확인했다. 이 검증은 실제 브라우저 동작 검증이 아니다. 추가한 제작 지침 두 문장도 별도 검토에서 범위·독립 사용 원칙과 모순되지 않음을 확인했다.

최종 예제 HTML의 SHA-256은 `399a3cbbcb29ac7c7458962fe6b1339ee2b10ea380b8e2ddb4dc41023d4affc6`이다. 역할 TOML 네 개·새 스킬의 SKILL.md와 UI YAML 여섯 쌍·새 공유 지침 두 개를 경로순으로 `상대경로 + NUL + 내용 + NUL`로 연결한 지침 집합 SHA-256은 `d65b78fc58c3e17ba0714faeaf1f404df57e53199d8dd50f74e1647f32f9323c`이다. 상대경로 기준은 `plugins/byko-stack-codex/`이며 README와 이 보고서는 집합에서 제외한다.

## 확인하지 못한 범위

Playwright의 번들 브라우저가 없었고 설치된 Chrome headless 실행은 실패했다. CUA가 로컬 `file:` 접근을 보안 정책으로 차단하고 우회 금지를 안내한 뒤 다른 경로로 시도하지 않았다. 따라서 실제 렌더링, 넓은·좁은 화면, 브라우저 클릭·키보드 탐색은 미검증이다. 소스 검사와 JavaScript 로직 확인이 이를 대신하지 않는다.

사용자 Codex에서의 native 역할 발견·설정 적용, 플러그인 설치 후 자동 스킬 선택, 실제 사용자 이해도, 일반적인 결함 탐지율·비용·속도는 검증하지 않았다. 후속 Stack 통합 시에는 실제 설치·실행 경로를 별도로 확인해야 한다.

## 2026-09-30 모델 기본값 변경

사용자 요청으로 네 역할의 기본 모델을 `gpt-6.1-sol`로 변경하고 노력 수준 `high`는 유지했다. TOML 파싱과 네 역할의 설정 일치를 확인했다. 역할 지침과 스킬은 변경하지 않았다. 위 독립 실행 결과와 지침 집합 hash는 변경 전 `gpt-6-sol` 구성의 기록이며, 새 모델에서의 행동 검증을 뜻하지 않는다. 새 모델로 실행 실험을 다시 수행하거나 사용자 설치본을 갱신하지는 않았다.
