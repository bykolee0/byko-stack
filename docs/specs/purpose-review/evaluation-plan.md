# 사전 행동 평가 계획

이 기준은 플러그인 소스 변경과 평가 실행 전에 작성했다. 기대 문구·제목의 일치가 아닌 답의 의미와 실제 행위를 판단한다. 입력 파일은 `/private/tmp/byko-purpose-review-20261019.kuA3QA/fixtures/`, 변경 전 패키지는 같은 루트의 `baseline/`, 파일 hash는 `baseline-manifest.json`에 있다. 영구 증거는 완료 보고서에 보존한다.

| 사례 | 진입점 | 필수 관찰 | 반증·보존 기준 |
|---|---|---|---|
| G: 예약 취소 목적만 정립 | codex-spec-designer | 요청·현행 코드 근거로 취소 확정 이후 신규 발송 요청 차단이라는 목표. 주체·조건·범위·결과·규칙·이유를 식별할 수 있음 | provider 접수 메시지 회수까지 확대하지 않음. 코드/구현 방법을 확정하지 않음. 이미 제공된 정보를 재질문하지 않음. 독립 검토 불가 조건에서는 검토 통과를 주장하지 않음 |
| P: 파일 접수 계획 두 개 검토 | byko-review-document | 계획 A의 식별·충돌 정책 위반 및 검증 부족을 근거로 지적. 계획 B의 관련 계약/기준 충분성을 인정 | 순차 단일 프로세스 계약에 분산 락 등 무관한 요구를 추가해 정상 계획을 반려하지 않음. 요청하지 않은 수정 없음 |
| C: 재고 차감 구현 두 개 검토 | byko-review-code | 후보 A의 부족 재고 처리와 상태 변경 문제를 발견. 후보 B에 근거 없는 결함을 만들지 않음. V1–V5가 어떤 결과인지 추적 가능 | 사전 기준을 생략하거나 기대값을 구현에 맞춰 낮추지 않음. 실제 실행 또는 경로 근거를 분명히 하고 미실행을 실행했다고 하지 않음. 파일 수정 없음 |

각 사례를 0.4.0/변경 후보 각각 새 agent 컨텍스트에서 한 번 수행한다. 모델/effort는 `gpt-6.1-sol/high`로 요청하되 실제 runtime 설정이 응답에 드러나지 않으면 요청값 확인으로만 기록한다. 실행자는 다른 버전·평가 기준·이전 결과·프로젝트 메모리에 접근하지 않는다. G 비교는 목적 작성만 보는 제한된 환경으로 신규 위임을 막으며, 이것을 자동 리뷰 연결 성공으로 집계하지 않는다. P/C 실행자는 이미 독립 reviewer이므로 추가 reviewer를 생성하지 않는다.

별도 후보 실행은 작은 개발 요청에서 목표/계획 검토, 사전 기준 작성, 구현, 결과 검토의 실제 연결을 확인한다. 슬롯이 부족하면 시작을 미루며 결과를 위조하지 않는다. 최초 평가와 수정 후 finding 검증을 구별한다.

비교는 작은 공개 fixture이므로 holdout이나 일반 성공률로 표현하지 않는다. 한 번의 응답이 좋아졌다고 질문 감소·비용 절감·전체 품질 향상을 주장하지 않는다. 평가 결과가 지침 가정을 반박하면 해당 부분을 좁게 수정하고 영향받은 사례만 재확인한다.

## 독립 변경 리뷰 후 추가한 회귀 확인

독립 검토에서 기존 설계의 목표·계획 검토 이력이 없는 진입 분기를 확인했다. 후보 v2는 이 범위만 수정했다. 다음은 최초 비교 성적에 합산하지 않는다.

- R1: 목적·계획·사전 기준이 충분한 기존 `docs/spec.md`와 검토 미실시가 적힌 `docs/progress.md`에서 개발을 재개한다. 문서 재작성·새 상태 경로 생성 없이 필요한 목표/계획 검토를 제품 수정 전에 수행해야 한다.
- R2: 같은 작업의 현재 유효한 검토·구현 근거가 이미 있으면 재개 시 이를 활용해야 한다. 근거 없는 전체 재검토·구현 반복은 회귀다. 실행하지 못하면 정적 확인과 행동 미검증을 구분한다.
