# Stack과 재사용 에이전트 연결

## 목적

사용자는 플러그인 설치만으로 공용 분석가·구현자·검토자·뷰어 생성자의 설정과 작업 방법을 재사용하고 싶다. 역할 설정은 플러그인 안의 TOML 한곳에서 관리하고, 전문 방법은 메인과 서브에이전트 모두 단독으로 사용할 수 있는 스킬에 둔다. 기존 Stack의 목적 중심 설계·개발·자동 독립 리뷰에 이 구성을 연결한다.

### 요구사항과 범위

- 네 역할은 `gpt-6.1-sol` / `high`를 기본값으로 사용한다. 동적 생성 시 실제 도구 인자에 설정을 전달하며 사용자 native 역할 등록을 전제로 삼지 않는다.
- 설치된 플러그인 루트에서 TOML·스킬·공유 지침을 찾는다. 원본 Git checkout, 형제 플러그인, 개인 cache 절대경로 없이 동작한다.
- 호출 시 작업 목적·대상·변경 범위를 전달한다. 코드만 조사하는 작업을 DB·로그 조사로 확대하지 않는다. 고정 입력 schema·문서 세트·에이전트 수·순서를 강제하지 않는다.
- 메인은 목적·설계 판단과 통합·완료 판단을 소유한다. 분리할 가치가 있는 조사·구현·사람용 자료 제작은 역할에 위임하고 작은 작업은 전문 스킬로 직접 수행할 수 있다.
- 설계와 구현의 자동 독립 리뷰, 설계 불일치의 재정립, 기존 문서·상태 계약과 사용자 변경 보존을 유지한다. 전문 리뷰 스킬과 이미 위임받은 reviewer가 다시 reviewer를 생성하지 않는다.
- 뷰어는 필요한 사람용 자료에 적용하며 형식 미지정 시 HTML이다. 기존 설계 문서를 무조건 HTML로 이관하거나 모든 작업에 뷰어를 만들지 않는다. 내용·시각화·탐색 검토와 실제 브라우저 확인을 구분한다.
- 생성 도구·요청 모델·검증 환경이 없으면 가능한 작업을 수행하고 공백을 명시한다. 자체 확인을 독립 검토로, 다른 모델을 TOML 적용으로 표시하지 않는다.
- 이번 범위는 `byko-stack-codex` 소스와 관련 안내·검증이다. Claude용 Stack, Goal, 전역 agent 등록, Git commit·push·공개 배포는 포함하지 않는다.

### 달성 조건

1. 기존 Stack 진입점에서 번들 TOML과 새 전문 스킬에 도달하고, 중복된 전문 지침은 한곳으로 정리된다.
2. Git checkout 밖으로 복사·설치된 패키지에서도 역할과 스킬 경로가 패키지 내부로 해석된다. 실제 CLI 설치가 가능한 범위에서 확인하고 단순 복사와 설치 검증을 구분한다.
3. 독립 실행에서 설계 전용 범위, 코드만 조사하는 범위, 구현·자동 리뷰·수정, 기존 상태 재개를 확인한다. 역할 지침과 `gpt-6.1-sol` / `high` 전달 근거를 기록한다.
4. 생성 기능이 없는 상황에서 허위 독립 리뷰 통과가 발생하지 않는다. HTML 실제 화면 확인이 불가능하면 해당 결과는 미검증으로 남는다.

## 방법과 근거

기존 `codex-spec-designer`, `codex-spec-dev`, `codex-review`를 workflow 진입점으로 유지한다. 전문 스킬 여섯 개는 독립 수행 단위로 남기고, 새 `shared/delegation.md`에서 위임 선택·패키지 상대 경로·생성 도구 적용·결과 통합을 설명한다. reviewer 생성은 `codex-review`가 담당하고 전문 리뷰 스킬은 직접 검토한다.

`scripts/prepare_agent.py`는 TOML 파싱과 번들 스킬 경로 해석만 수행하는 표준 라이브러리 도구로 둔다. 자체 agent runtime을 만들지 않는다. `model`, `reasoning_effort`, 역할 지침과 해당 스킬 경로를 반환하며 목적·범위는 호출자가 자연어로 추가한다. helper를 실행할 수 없으면 같은 파일을 직접 읽을 수 있다. 읽기 실패나 누락된 패키지를 다른 역할·모델로 조용히 대체하지 않는다.

기존 리뷰 참조 경로는 새 전문 스킬을 가리키는 짧은 연결 문서로 유지한다. 기존 사용자 문서·호출 경로를 불필요하게 깨지 않는다. workflow와 전문 스킬 description은 조율 요청과 개별 수행 요청을 구분하고 자동 선택 기본값은 유지한다.

설치·런타임 규격은 최신 [플러그인 패키징](https://developers.openai.com/plugins/build/plugins), [매니페스트](https://developers.openai.com/plugins/deploy/submission), [서브에이전트](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 기준으로 확인한다. 현재 `.codex-plugin/plugin.json` 형식은 유지하고 소스 버전을 `0.4.0`으로 올린다. 전역 설정을 바꾸지 않는 검증을 우선한다.

검증은 TOML·YAML·매니페스트·참조 경로 검사, helper의 이동된 패키지·오류 입력 검사, 실제 독립 agent 시나리오로 나눈다. 새 브라우저 확인은 현재 권한이 허용하는 경우에만 수행하며 앞서 차단된 접근을 우회하지 않는다. 모든 검증은 임시 작업공간에서 수행한다.
