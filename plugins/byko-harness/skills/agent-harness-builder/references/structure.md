# 하네스 구조와 문서 규격

스킬이 리포에 만드는 트리, 파일마다의 규격, 템플릿을 정한다. 리포 AGENTS.md의 "문서 규격" 절에는 맨 아래 [규격 블록](#agentsmd에-넣는-문서-규격-블록)을 리포의 문서 언어로 옮겨 넣는다. 에이전트가 문서를 쓰는 순간 그 규격이 컨텍스트에 있어야 지켜지기 때문이다.

## 트리와 역할

```
<repo>/
├── AGENTS.md          중심: 개요·목표, 영역 색인, 코드 규칙, 문서 규격, 명령, 미결정, 지식 관리
├── CLAUDE.md          @AGENTS.md (+ Claude 전용 내용만)
└── docs/
    ├── wiki/          지금 기준의 최종 정의(SSOT)
    │   ├── policies/  정책(중추) + index.md
    │   ├── domain.md · architecture.md · infrastructure.md · deploy.md · testing.md
    ├── records/       결정·작업 기록(로그)
    └── references/    참고 자료 + index.md
검사: 리포 test 도구 안의 하네스 규격 검사 + 꼭 지킬 정책의 강제 검사
```

| 자리 | 역할 | 관리 방식 |
|---|---|---|
| `AGENTS.md` | 항상 로드되는 중심 파일. Codex는 이 파일을, Claude Code는 CLAUDE.md가 가져온 것을 읽는다 | 짧게 유지, 링크·크기 검사 |
| `CLAUDE.md` | `@AGENTS.md` 한 줄과 Claude에만 필요한 내용. 아래 "CLAUDE.md와 하위 폴더" 참고 | 가져오기 줄 검사 |
| `docs/wiki/` | 이 리포의 최종 결과를 정의한다. 여기를 보면 결과를 알 수 있어야 한다 | 규격 검사 + 유지 모드 |
| `docs/records/` | 쓴 시점의 결정·작업 기록. 지금 기준과 맞추지 않는다 | 관리 의무 없음 |
| `docs/references/` | 외부 문서 요약, 리포에서 명령으로 뽑은 자료(스키마 덤프·API 명세 등), 이미지 | index로 관리 |

페이지와 폴더는 내용이 생길 때만 만든다. 트리를 다 채우는 것이 목표가 아니다. 빈 자리는 다음 에이전트에게 "여기 무언가 있어야 한다"는 거짓 신호가 되고, 아무도 관리하지 않아 낡는다.

### 놓는 자리

- 기본 위치는 위 트리다. 같은 역할의 자리가 리포에 이미 있으면 그 경로를 쓰고, 문서 규격 블록과 검사의 경로 상수에 적는다.
- docs/가 문서 사이트나 출판의 원본이면(Sphinx, MkDocs, Docusaurus, GitHub Pages 등) 설정으로 확인한다. 그 안에 둔 wiki·records·references가 빌드에 잡히거나 공개 사이트에 실리는지 본다. 예를 들어 MkDocs는 docs/ 안의 마크다운을 모두 싣는다. 실리면 빌드 제외 설정을 더하거나 다른 위치를 쓰고, 이유를 보고한다. 내부 정책과 미결정이 공개되면 안 되기 때문이다.

### CLAUDE.md와 하위 폴더

- Claude Code는 작업 폴더나 그 위에 CLAUDE.md가 있으면 AGENTS.md를 직접 읽지 않는다. 그래서 CLAUDE.md에 `@AGENTS.md`를 두어 가져오게 한다.
- CLAUDE.md가 없으면 최근 Claude Code(2.1.277 이후)는 AGENTS.md를 직접 읽는다. 그래도 CLAUDE.md를 둔다. 직접 읽지 못하는 세션(이전 버전, 그 기능을 끈 경우)에서도 읽히게 하고, Claude 전용 내용을 둘 자리이기 때문이다.
- 하위 폴더에 AGENTS.md가 있으면 그 옆에도 `@AGENTS.md`를 담은 CLAUDE.md를 둔다. 루트에 CLAUDE.md가 생기면 Claude Code는 하위 폴더의 AGENTS.md도 읽지 않는다. 하위 폴더의 CLAUDE.md는 그 폴더의 파일을 다룰 때 읽힌다.
- 가져오기 줄은 코드 블록이나 인라인 코드 밖에 쓴다. 그 안의 가져오기는 무시된다.

## AGENTS.md

리포의 문서 언어로 쓰고, 해당 내용이 없는 절은 뺀다.

1. **제목과 개요·목표**: 무엇을 왜 만드는지 몇 줄. 코드를 읽으면 알 수 있는 설명(파일 배치, 보이는 구조)은 넣지 않는다. 설명형 개요는 에이전트가 관련 파일을 찾는 데 도움이 되지 않았다.
2. **`## 색인`**: 영역 단위로 가리킨다. 항목마다 마크다운 링크, 무엇이 있는지, 언제 여는지를 적는다. 세부 목록은 폴더의 index.md가 맡는다.
   - 열지 말지를 에이전트가 정하는 문서는 잘 열리지 않는다. 그래서 "언제 여는지"를 구체적인 상황으로 쓴다. 예: "기능 동작·데이터·권한을 바꾸는 변경 전".
3. **`## 코드 규칙`**: 코드에서 보이지 않거나 표준과 다른 전역 규칙만 쓴다. "~하지 않는다", "~만 쓴다" 꼴로 짧게 쓴다.
   - formatter·linter 설정이 정하는 것과 주변 코드에서 보이는 관례는 쓰지 않는다. 원본은 그 설정과 코드다.
   - 계층·의존 방향 같은 구조 규칙은 architecture.md에, 특정 영역만의 규칙은 그 영역 정책 페이지에 둔다.
4. **`## 문서 규격`**: 아래 규격 블록을 넣는다.
5. **`## 명령`**: 빌드·테스트·실행 명령 가운데 코드만 봐서는 모르는 것을 둔다. 명령 줄의 원본은 여기이고, wiki는 이름으로 가리킨다. 같은 줄을 두 곳에 쓰면 한쪽만 고쳐져 낡는다.
6. **`## 미결정`**: 에이전트가 혼자 정하면 안 되는 것과, 근거가 서로 어긋나 정책으로 쓰지 못한 것을 둔다. 항목마다 무엇이 충돌하는지와 근거 위치를 적는다.
7. **`## 지식 관리`**: 아래 내용을 리포 언어로 옮긴다.
   - 작업 중 wiki의 정의와 코드가 다른 것을 발견하면 정의를 고치지 말고 보고한다. 코드가 틀렸을 수도 있다. 근거로 맞추는 일은 하네스 유지 작업에서 한다. 코드 현황을 옮겨 적은 부차 설명만 바로 고쳐도 된다.
   - 정책이나 구조를 바꾸는 작업이면 마칠 때 해당 페이지와 `verified`를 갱신한다.
   - 탐색·계획을 하위 에이전트에게 맡길 때는 관련 wiki 경로를 지시에 넣는다. 하위 에이전트는 이 파일을 받지 못할 수 있다.
   - 결정·작업 기록은 records 위치에 남긴다.

크기는 200줄 미만(Claude Code 권장)과 32KiB 이하(Codex가 읽는 AGENTS.md 합계 상한)로 유지한다. 넘치면 세부를 wiki로 옮기고 색인만 남긴다. 이미 있던 AGENTS.md를 줄이는 기준은 [playbook-existing.md](playbook-existing.md)를 따른다.

## wiki 페이지

### 프론트매터

검사가 읽을 수 있게 단순한 형식만 쓴다.
- 한 줄에 `키: 값`을 쓴다.
- 목록은 `[a, b]`로 쓰고, 항목 안에는 쉼표를 넣지 않는다.

| 키 | 뜻 | 대상 |
|---|---|---|
| `title` | 페이지 이름 | 모든 페이지 |
| `summary` | 한 줄 요약. 색인과 검색에 쓰인다 | 모든 페이지 |
| `scope` | 적용 범위. 경로와 기능 이름 목록 | 모든 페이지 |
| `sources` | 근거. 리포 경로(코드·문서·records) 또는 URL. 경로 뒤에 `:줄`을 붙여도 된다. 사람의 결정은 records에 남긴 뒤 그 경로를 적는다 | 모든 페이지 |
| `verified` | 마지막으로 근거와 대조한 날짜와 그때의 커밋(`git rev-parse --short HEAD`). 리포에 아직 커밋이 없으면 날짜만 쓴다 | 모든 페이지 |
| `status` | `confirmed`(사람이 한 말이나 결정 기록이 근거) 또는 `from-code`(리포 안의 근거로 정리). 한 페이지에 둘이 섞이면 `from-code`로 두고, 사람이 정한 규칙은 본문에서 그 결정 기록을 링크한다. 유지 작업은 규칙마다 근거를 본다 | 정책 |
| `enforced_by` | 이 정책을 강제하는 검사 파일 경로. 없으면 `[]` | 정책 |

### 본문

- 첫 `## ` 절은 `## 정의`다. 리포 문서가 영어면 `## Definition`을 쓰고, 규격 블록과 검사도 같은 값으로 맞춘다.
- 정의는 이 페이지를 보면 알 수 있어야 하는 최종 결과다. 이유·예외·적용처럼 부차적인 절은 필요할 때만 그 아래에 둔다. 판단은 정의가 기준이고, 부차 설명은 정의를 돕는 데 그친다.

### 페이지마다 담을 것

- **`policies/<영역>.md`**: 그 영역 규칙의 최종 정의. 사람에게 넘길 판단 경계도 적는다. 꼭 지켜야 하는데 문서만으로는 막을 수 없는 규칙은 강제 검사를 만들고 `enforced_by`에 적는다.
- **`domain.md`**: 개체와 용어의 정의, 그리고 관계(무엇이 무엇을 소유·발생·참조하는지). 코드는 링크가 아니라 이름으로 가리킨다. 이름은 검색되고 링크는 낡는다.
- **`architecture.md`**: 최종 구조의 정의.
  - 담는 것: 경계, 의존 방향과 계층 규칙(구조에 관한 관례), 전역 데이터 흐름(예: 이벤트 큐를 거치는 경로), "~는 ~에 의존하지 않는다" 꼴의 불변식.
  - 파일 배치는 쓰지 않는다. 다만 폴더 이름만으로 구조가 드러나지 않으면 최상위 폴더 지도는 둔다.
- **`infrastructure.md`**: 실행 환경, 외부 의존, 자원, 설정과 비밀값이 어디서 오는지. 비밀값 자체는 쓰지 않는다.
- **`deploy.md`**: 배포 절차, 조건, 되돌리는 방법의 정의.
- **`testing.md`**: 결과를 확인하는 방법. 테스트 종류와 범위, 앱을 띄워 관찰하는 방법, 테스트 데이터. 명령은 AGENTS.md의 이름으로 가리킨다.

한 페이지가 커지면 같은 이름의 폴더와 index.md로 나눈다(예: `architecture/index.md`).

## index.md

- wiki의 하위 폴더(policies/, 나뉜 페이지 폴더)와 references/에 둔다. references의 하위 폴더는 자기 index.md를 둘 수 있고, 그러면 그 폴더의 파일은 그 index.md가 싣는다. records에는 두지 않는다. 기록은 이름 규칙으로 찾는다.
- 항목 형식
  - 기본: `- [파일](상대경로) — 한 줄 요약 · 범위`. 정책이면 상태를 덧붙인다.
  - references: 기본 형식에 왜 두는지, 출처(URL과 버전, 또는 만드는 명령), 언제 보는지를 더한다.
- 폴더의 모든 파일이 실려 있어야 하고, 없는 파일을 가리키면 안 된다(검사 대상). 색인에 없는 파일은 왜 있는지 모른 채 남는다.

## records (최소 규칙)

- 평평한 폴더다. 파일 이름은 `YYYY-MM-DD-<종류>-<제목>.md`로 짓는다. 종류는 decision, work, incident 등이다. 파일이 여러 개 필요하면 같은 이름의 폴더를 쓴다.
- 프론트매터는 선택이다: `type`, `status`(in-progress, done), `related`(영향받은 wiki 페이지).
- 진행 중에는 고치고, 끝난 기록은 고치지 않는다. 지금 기준은 wiki가 말한다.
- 큰 변경의 권장 형식: 목표·범위 / 구현 전 검증 기준 / 미결정과 상태 / 검증 결과.
- 기존 리포에 이미 결정·작업 기록 위치가 있으면(예: `docs/adr/`), 보완 모드에서는 그 위치를 records로 삼아 색인에 적는다.

## references

- 모든 파일이 index.md에 실린다. 이미지·PDF는 index의 설명이 검색 대상이 된다.
- 리포에서 명령으로 뽑은 자료(스키마 덤프, API 명세, 생성 타입)는 index에 만드는 명령을 적고, 손으로 고치지 않는다. 같은 내용이 코드에서 바로 읽히면 두지 않는다.
- 외부 문서 요약에는 기준 버전이나 날짜를 적는다.

## AGENTS.md에 넣는 문서 규격 블록

리포 언어로 옮긴다. 경로(`docs/wiki`, `docs/records`, `docs/references`)는 이 리포가 실제로 쓰는 위치로 바꾼다. 예를 들어 기존 `docs/adr/`를 기록 위치로 삼았으면 그 경로를 쓴다. `<검사 파일>`도 실제 경로로 바꾼다. 검사 파일의 경로 상수와 정의 제목도 이 블록과 같게 맞춘다.

```markdown
## 문서 규격
- docs/wiki: 지금 기준의 최종 정의(SSOT). 맨 위 프론트매터에 title·summary·scope·sources·verified(`YYYY-MM-DD <짧은 커밋>`, 커밋이 없으면 날짜만)를 두고, 정책 페이지는 status(confirmed·from-code)·enforced_by를 더한다. 목록은 `[a, b]`로 쓰고 항목에 쉼표를 넣지 않는다. 본문 첫 절은 `## 정의`다.
- wiki 루트의 페이지·폴더와 docs/references는 이 파일의 색인에 링크한다. wiki의 하위 폴더와 docs/references에는 index.md를 두고 모든 파일을 링크로 싣는다. references의 하위 폴더가 자기 index.md를 두면 그 폴더의 파일은 그 index.md가 싣는다.
- sources에는 리포 경로(뒤에 `:줄` 가능)나 URL을 쓴다. 사람의 결정은 docs/records에 남긴 뒤 그 경로를 쓴다.
- docs/records: `YYYY-MM-DD-<종류>-<제목>.md`. 끝난 기록은 고치지 않는다.
- docs/references: index.md에 무엇·왜·출처(또는 만드는 명령)·언제 볼지를 적는다.
- 이 규격은 `<검사 파일>`이 검사한다.
```

## 템플릿

### CLAUDE.md

파일에는 코드 블록 표시 없이 아래 줄만 쓴다. Claude 전용 내용이 있으면 그 아래에 둔다.

```markdown
@AGENTS.md
```

### 정책 페이지

형식만 보여 주는 예다. 내용과 경로는 그 리포의 근거에서 나와야 하고, `verified`의 날짜와 커밋은 실제 값으로 쓴다.

```markdown
---
title: 환불 정책
summary: 환불 가능 기간·금액·승인 조건의 최종 정의
scope: [src/billing/refund, POST /refunds]
status: from-code
enforced_by: [tests/policies/test_refund_policy.py]
sources: [src/billing/refund/service.py:42, tests/billing/test_refund.py]
verified: <대조한 날짜> <git rev-parse --short HEAD>
---
## 정의
- 결제 후 14일이 지나면 환불하지 않는다.
- 부분 환불 합계는 결제 금액을 넘지 않는다.

## 사람에게 넘길 경우
- 14일이 지난 건의 예외 처리 요청.
```

```markdown
# 정책
- [환불](refund.md) — 환불 기간·금액·승인 조건 · src/billing/refund · from-code
```
