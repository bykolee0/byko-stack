# 새 개발 리포

코드가 아직 없거나 거의 없는 리포다. 정할 것은 대부분 사람의 머릿속이나 대화에 있으니, 질문으로 결정을 모으는 것부터 한다. 코드에서 뽑을 근거가 없으므로 정책은 대부분 `confirmed`가 된다.

## 1. 결정 모으기

이미 대화나 요청에 나온 것은 다시 묻지 않고, 요약해서 맞는지만 확인한다. 질문은 한 번에 3개 이내로 하고, 구조와 검사를 정하는 데 걸리는 것부터 묻는다.

- 무엇을 왜 만드는가, 첫 마일스톤은 무엇인가
- 정해진 스택은 무엇인가: 언어, 프레임워크, 패키지 관리자, 저장소, 배포 대상, 테스트 도구
- 이미 정한 정책: 데이터(보존·개인정보), 권한, 보안, 공개 API, 과금 등. 아직 열어 둔 결정과, 에이전트가 혼자 정하면 안 되는 결정도 묻는다.
- 이미 정한 구조: 모듈·서비스 경계, 데이터가 흐르는 길(큐·이벤트 등), 외부 연동
- 문서 언어와 팀 관례

사람이 대화에 없는 실행이면 요청에 적힌 내용으로 진행한다. 빈 곳은 AGENTS.md "미결정"에 남긴다.

## 2. 만들기

[structure.md](structure.md)의 규격대로 만들되, 내용이 있는 것만 만든다.

- **결정 기록:** 위에서 받은 결정을 `docs/records/YYYY-MM-DD-decision-<제목>.md`에 남긴다. 정책 페이지의 `sources`가 이 파일을 가리킨다.
  - 사람의 말은 원문 그대로 인용한다. `confirmed`는 이 원문이 근거다. 비밀값·개인정보가 섞여 있으면 그 부분만 가린다.
  - 모델이 원문을 풀어 쓰거나 범위를 넓힌 부분은 정책 페이지에 "해석"으로 표시하고, 미결정에 확인 항목으로 올린다.
- **AGENTS.md:** 아래 절을 둔다.
  - 개요·목표
  - 색인: 만든 영역만
  - 코드 규칙: 정해진 것만
  - 문서 규격
  - 명령: 정해진 것만
  - 미결정
  - 지식 관리
- **CLAUDE.md:** `@AGENTS.md`
- **wiki:** 정해진 내용만 페이지로 만든다.
  - 정책 페이지: 사람이 정한 정책. 상태는 `confirmed`로 둔다.
  - architecture.md: 의도한 경계와 흐름이 정해졌을 때
  - testing.md, deploy.md: 확인 방법과 배포 방식이 정해졌을 때
- **references:** 넘겨받은 외부 자료가 있을 때만 만든다.

## 3. 검사

- 정해진 테스트 도구로 하네스 규격 검사를 만들고 실행한다([checks.md](checks.md)).
- 검사를 돌리는 데 필요한 최소 설정만 만든다. 예: 테스트 도구 설정, 개발 의존성 한 줄.
- 앱 골격(소스 폴더, 프레임워크 설정, 예제 코드)은 만들지 않는다. 하네스가 할 일이 아니다.
- 지금 강제할 수 있는 정책 검사가 있으면 함께 만든다.
- 테스트 도구가 아직 정해지지 않았으면 도구를 대신 고르지 않는다. "검사 도구 미정"을 미결정에 올리고 "기초만 됨"으로 보고한다.

## 4. 마무리

[SKILL.md](../SKILL.md)의 "완료와 보고"를 따른다. 새 리포는 정책이 사람의 결정에서 오므로 독립 검토는 대개 필요 없다. 대신 정책 페이지가 결정 기록과 같은 말을 하는지 직접 대조한다.
