# 실제 동작과 변경 영향 검토

[검토 공통 기준](../../shared/review-principles.md)을 따른다. 메인 또는 이미 위임받은 검토자 모두 이 스킬로 직접 검토할 수 있다.

## 기준과 흐름

현재 repo·대상 변경·비교 base를 확인한다. 원래 목적, 기대 결과, 보존할 계약에서 중요한 정상·실패·경계 상황을 정한 뒤 구현과 대조한다. 문서가 목적을 누락했거나 기존 시스템의 보안·호환성 정책과 충돌하면 스펙 준수만으로 통과시키지 않는다.

[사전 검토 기준](../../shared/verification.md)을 받아 중요한 항목의 결과·근거·미검증을 빠짐없이 대조한다. 새 구현과 그 테스트에서만 정답을 도출하지 않는다. 기준 변경·삭제는 원래 요구와 근거로 검토하며 새로 드러난 위험을 보완한다. 기존 기준이 없는 과거 변경도 검토할 수 있지만 사전 작성했다고 주장하지 않는다.

실제 호출자부터 변경이 닿는 저장·queue·외부 서비스·runtime consumer까지 관련 경로를 추적한다. API·schema·직렬화·권한·tenant 격리, 트랜잭션·중복·순서·재시도·취소, 혼합 버전·롤백·성능 중 해당 변경에 중요한 축을 선택한다. 모든 프로젝트에 backend 체크리스트를 강제하지 않는다.

작성자의 영향 범위나 인계 요약을 조사 상한으로 삼지 않는다. 중요한 결론이 다른 리포·인프라·서드파티 계약에 의존하면 허용된 범위에서 확인한다. 데이터 자체의 값·상태·제약과 생성·전달·소비 흐름은 구별한다. 작은 diff라는 이유만으로 정책·외부 계약·과거 정상 동작의 검토를 생략하지 않는다.

구조·컨벤션·주 흐름의 가독성·책임 중복·불필요한 추상화는 실제 유지보수 영향으로 판단한다. 취향만 다른 코드를 결함으로 만들지 않는다.

## 반증과 실행

구현이 가정한 조건이 깨져도 목적이 충족되는지 확인한다. 입력·사전 상태·기대 결과와 근거를 정하고 가장 작은 유효한 재현을 실행한다. 반환값뿐 아니라 관련 저장 상태·식별자·전송 payload·이벤트·실패 후 부수 효과를 관찰한다. mock 사이에 빠진 연결을 확인한다.

필요한 targeted 검사와 실제 경계 확인에 집중한다. 실패가 변경으로 생겼는지 불명확하면 base에서도 확인한다. 구현자가 이미 본 사례나 구현 후 만든 반례를 holdout이라고 부르지 않는다. 검증되지 않은 가정은 별도 공백으로 남긴다.

기존 검증 harness와 현재 버전의 실행 근거를 먼저 확인한다. 방법에 공백이 있으면 허용된 임시 환경에서 필요한 관찰만 보완하고 실제 실행 여부를 구분한다. 검증 방법이 있다는 사실, CI·배포 성공만으로 실제 사용자 결과를 입증했다고 보지 않는다. 중요한 변경 전/후 기대값과 보존 결과를 대조한다.

## 반환

판정과 영향이 큰 발견 사항부터 전달한다. 파일·라인, 기대/실제 차이, 실패 조건과 영향, 최소 수정 방향과 필요한 회귀 검증을 포함한다. 수행한 검사와 미검증 경계를 구분한다. 검토 대상을 수정하거나 별도 종합 리뷰 workflow를 자동 호출하지 않는다.

마무리 검토라면 원래 요청·목표와 실제 사용 경계의 결과까지 대조한다. 개별 단위만 통과하고 결합된 결과를 확인하지 못했다면 그 공백을 남긴다. 코드 문제와 목표·계획 문제의 원인을 구분해 호출자에게 반환한다. 정상 구현에 finding을 만들 의무는 없다.
