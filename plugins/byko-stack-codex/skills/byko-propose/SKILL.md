# 근거에 맞는 방법 후보

[작업 계약](../../shared/task-contract.md)을 읽고 적용한다. 특정 문서 양식이나 선행 스킬을 전제하지 않는다. 맡은 후보를 작성해 반환하며 reviewer나 전체 설계·개발 workflow를 호출하거나 다른 agent를 생성하지 않는다.

## 기준과 실제 대상

원래 요청·목표·정정, 보존 조건, 기대 결과·관찰 방법, 허용·제외 범위를 확인한다. 요약은 길잡이로 사용하고 중요한 결정이 의존하는 원자료·현재 코드·인접 계약을 직접 대조한다. 누락된 연결이 보이면 허용 범위에서 확인한다. 기존 코드가 곧 올바른 정책이라는 전제를 두지 않는다.

사용자만 정할 정책이나 결론을 바꿀 근거가 없으면 그 공백과 영향을 반환한다. 부족한 기준을 조용히 만들어 후보를 완성하지 않는다. 다른 후보나 예상 승자를 참고하지 않도록 위임받았다면 지정한 경계를 지킨다.

## 작성과 반환

목표를 만족하는 구체적인 동작·책임 경계·관련 계약과 구현 순서, 실패 처리, 검증 방법을 제안한다. 현재 구조를 재사용할 수 있는지 먼저 확인하고 불필요한 상태·계층·설정을 추가하지 않는다. 원하는 결과와 방법을 구별한다.

반환에는 선택한 접근과 이유, 성립 조건, 대안·단점, 실패할 반례, 보존·검증 접근, 남은 결정을 담는다. 하나의 방법만 타당하면 그 제약을 설명하고 억지 대안을 만들지 않는다. 실행하지 않은 관찰을 검증 결과로 쓰지 않는다.

허용된 문서 위치가 있으면 담당 범위만 갱신하고 없으면 응답으로 반환한다. 제품 코드·설정·데이터를 수정하지 않는다. 이 결과는 작성자의 후보이며 독립 검토 통과나 최종 채택이 아니다. 반려되면 지적된 전제·차이·근거에 필요한 부분만 보완한다.
