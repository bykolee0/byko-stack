# 목적에 대한 독립 검토

[공통 workflow](../../shared/workflow.md)와 [검토 기준](../../shared/review-principles.md)을 따른다. 이 스킬은 독립 검토의 구성·결과 통합을 담당한다. 실제 검토 방법은 대상에 맞는 전문 스킬을 사용한다.

## 대상과 전문 지침

원래 요청·관련 계약에서 목적과 검토 범위를 확인한다. 파일 확장자만으로 모드를 고르지 않고 판단할 내용에 맞춰 아래 지침을 선택한다. 구현 리뷰에도 원래 목적과 설계의 검토가 포함되므로 같은 평가를 다시 실행하지 않는다.

| 판단할 것 | 적용할 스킬 |
|---|---|
| 설계·계획·분석의 목적·논리·근거 | [byko-review-document](../byko-review-document/SKILL.md) |
| 실제 동작·계약·회귀·주변 영향 | [byko-review-code](../byko-review-code/SKILL.md) |
| 사람의 이해·시각화·탐색 UX | [byko-review-viewer](../byko-review-viewer/SKILL.md) |

복합 대상에는 필요한 지침을 함께 적용한다. 이전 `spec`·`plan` 요청은 문서 검토로 이어받는다. 필요한 원문·버전이 없으면 직접 찾고, 중요한 기준을 확정할 수 없는 부분만 미검증으로 남긴다.

## 독립 컨텍스트 구성

리뷰를 시작하는 호출자는 [번들 역할 위임](../../shared/delegation.md)에 따라 `byko-reviewer` TOML을 읽고 현재 도구로 독립 agent를 생성한다. 원래 요청·목적의 출처, 대상 문서·diff·관련 경로와 필요한 전문 스킬 경로를 전달한다. 예상 결론·의심 버그·이전 판정·전체 구현 서사는 전달하지 않는다.

이미 독립 reviewer로 위임받았다면 전문 스킬을 직접 수행해 반환한다. reviewer와 전문 스킬은 또 다른 reviewer나 설계·개발 workflow를 자동 호출하지 않는다. 큰 변경에서는 독립적으로 확인할 범위가 있을 때만 여러 reviewer를 쓰고, 광역 검사는 한 실행자가 소유한다.

생성 도구·정책·모델 지원 때문에 독립성을 확보할 수 없으면 가능한 직접 검토를 수행하되 독립 검토 미실시를 명시하고 `미검증`으로 반환한다. 다른 모델이나 외부 프로세스로 조용히 우회하지 않는다. 이미 독립 컨텍스트에서 작업하는 reviewer에게 이 생성 조건을 다시 요구하지 않는다.

## 결과 통합과 수정 책임

호출자는 reviewer의 중요한 주장을 원문·코드 경로·필요한 실행 근거와 대조한다. 이미 충분한 근거가 있는 검증 전체를 반복하지 않는다. 독립 검토 후 이전 판정과 비교해 누락·오탐을 살필 수 있다. 다수 의견이나 테스트 통과 수로 판단하지 않는다.

판정은 `통과 / 수정 필요 / 미검증`과 대상·버전·범위를 함께 반환한다. 핵심 실행·화면 확인을 못 했거나 독립성이 필요한데 확보하지 못했다면 그 부분을 통과로 확대하지 않는다. 자세한 finding 기준은 공통 검토 기준과 전문 스킬을 따른다.

리뷰는 read-only다. 디자인·개발에서 자동 호출됐다면 호출자가 유효한 발견 사항을 수정하고 영향받은 부분을 재검토하며 [문서 관리](../../shared/artifacts.md)에 따라 근거를 기록한다. 단독 리뷰 요청은 응답으로 결과를 제공하고, 파일·PR·외부 게시를 요청받지 않았다면 쓰기를 하지 않는다.
