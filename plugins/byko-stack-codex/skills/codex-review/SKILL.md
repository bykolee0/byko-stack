# 목적에 대한 독립 검토

[공통 원칙](../../shared/workflow.md)을 따른다. 문서는 목적을 달성할 수 있는 설계인지, 구현은 실제로 목적을 충족하고 기존 시스템에 적절히 통합되는지 판단한다. 스펙 준수와 원래 목적에 대한 적합성을 함께 본다.

## 대상과 기준

사용자 요청·관련 문서에서 요구사항을 포함한 목적과 그 근거를 파악한다. 제시된 방법이나 현재 구현을 목적의 대용으로 삼지 않는다. 문서가 원래 의도를 누락·축소했거나 완료 기준이 수단 수행에 머무르면 그 자체가 검토 대상이다. 기대 결과가 불명확하면 구현에서 정답을 만들어내지 않는다.

대상에 맞는 지침만 읽는다.

- **문서**: 스펙·설계·구현 계획은 [문서 검토](references/design-review.md). 기존 `spec`·`plan` 요청도 여기에 해당한다.
- **구현**: 코드·브랜치·기능 변경은 [구현 리뷰](references/implementation-review.md).

별도 명령 없이 현재 대상에서 모드를 판단한다. 구현 리뷰에도 설계 문서와 목적 검토가 포함되므로 문서 평가를 중복 실행하지 않는다.

## 독립성

리뷰를 시작하는 호출자가 현재 실행 정책이 허용하는 독립 subagent를 구성한다. 새 컨텍스트에 원래 요청·목적의 출처, 대상 문서·diff·관련 경로와 이 리뷰 지침을 제공한다. 호출자의 예상 결론·의심 버그·이전 평가 결과는 독립 검토 전에 제공하지 않는다. 전체 대화의 구현 서사를 복제하지 않는다.

이미 독립 reviewer로 위임받은 agent는 대상 검토를 직접 수행해 반환한다. 독립성을 충족한다는 이유로 또 다른 reviewer를 만들지 않는다. 아래 도구 부재 조건은 독립 컨텍스트를 아직 확보하지 못한 호출자에게 적용한다.

검토자는 목적에서 기대 동작과 중요한 반례를 먼저 정리하고 대상 방법·구현과 대조한다. 역할과 수는 독립적으로 확인할 과제가 있을 때만 늘린다. 광역 테스트는 한 실행자가 소유하고 나머지는 필요한 작은 재현에 집중한다.

독립 도구가 없거나 정책상 금지되면 현재 세션에서 가능한 검토를 진행하되 독립 검토 미실시를 명시하고 `미검증`으로 반환한다. 같은 컨텍스트의 점검을 독립 검토 통과라고 부르지 않는다. 외부 모델·프로세스를 임의로 호출해 우회하지 않는다.

## 발견 사항과 판정

메인은 reviewer의 주장을 코드 경로·실행 반례·원문 등 실제 근거로 재확인한다. 확인 뒤 이전 리뷰와 비교해 누락·오탐을 살필 수 있다. 다수 의견이나 테스트 통과 수로 판정하지 않는다.

발견 사항에는 목적상 기대 결과, 실제 차이, 파일·라인 등 근거, 영향과 필요한 수정 방향을 적는다. 재현하지 못했어도 경로상 입증되는 문제는 근거를 설명하고, 단순 가능성은 미검증 위험으로 구분한다. 취향이나 무관한 범위 확장을 필수 수정으로 만들지 않는다.

- **통과**: 해당 대상·버전에서 목적에 대한 판단 근거가 충분하고 해결해야 할 중요한 문제가 없다.
- **수정 필요**: 목적·설계·구현의 정합성 또는 실제 동작에 근거 있는 문제가 있다.
- **미검증**: 중요한 기대 결과·독립성·실행 근거가 부족해 통과를 판정할 수 없다.

통과는 검토한 대상과 범위에 한정된다. 문서 통과는 구현 완료를, 로컬 검증은 운영 환경 검증을 뜻하지 않는다. 실제 결과가 목적을 충족했는지 설명할 수 있어야 구현 통과를 판단한다.

## 결과 전달과 수정 책임

리뷰 자체는 read-only다. 소스·설계를 고치지 않고 발견 사항을 반환한다. 허용된 테스트와 임시 재현은 저장소·외부 상태를 훼손하지 않는 환경에서 수행한다.

디자인·개발에서 자동 호출됐으면 호출자가 발견 사항을 반영하고 [문서 관리](../../shared/artifacts.md)에 따라 현재 상태와 검토 근거를 기록한다. 리뷰어는 다른 스킬을 다시 호출해 수정 루프를 만들지 않는다. 단독 리뷰는 사용자가 요청한 범위에서 결과를 보고하며, 파일·PR·외부 게시를 요청받지 않았다면 응답만 제공한다.

판정과 근거 있는 중요한 발견 사항을 먼저 보고하고, 확인한 목적·범위·검증 결과·남은 위험을 설명한다. 문제가 없을 때는 확인한 범위에서 발견하지 못했다고 표현한다. 고정된 긴 결과 양식을 요구하지 않는다.
