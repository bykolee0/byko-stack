# 문서 검토

목적에 포함된 요구사항과 달성 조건에서 출발해 제안된 방법이 그 결과를 만들 수 있는지 검토한다. 단순히 문서의 항목이 채워졌는지 확인하는 데서 끝내지 않는다.

## 목적과 방법

원래 요청·문제의 근거와 목적 문서를 대조한다. 사용자에게 필요한 결과가 빠지거나 수단으로 바뀌지 않았는지, 요구사항·범위·보존 조건·달성 기준이 하나의 목적 안에서 일관되는지 본다. 파일 생성·등록·검사 통과만으로 결과를 대신하는 완료 기준은 충분하지 않다.

현재 코드·관련 계약을 확인하고 방법의 전제가 실제로 성립하는지 판단한다. 방법 선택의 이유가 목적과 연결되는지, 필요한 통합·실패 처리·호환성·운영 영향이 고려됐는지 살핀다. 관련 없는 항목을 형식적으로 추가하지 않는다.

## 설계를 반증하기

제안된 방법을 따랐는데도 목적을 이루지 못하는 입력·상태·사용 흐름을 찾아본다. 정상 흐름뿐 아니라 보존해야 하는 동작, 중요한 실패·경계 상황을 기준으로 방법의 약한 전제를 확인한다. 아직 구현이 없다는 이유로 구현 수준의 테스트 실행을 문서 통과 요건으로 요구하지 않는다.

구현 계획을 검토할 때는 작업을 다 끝내도 목적이 남는지, 필요한 의존 관계와 검증이 빠졌는지 본다. 파일 목록·AC 표의 존재를 정확성의 대리값으로 쓰지 않는다.

검증 계획은 실제 결과를 관찰할 수 있어야 한다. 내부 호출 mock만 확인해 중요한 저장·전송·사용 결과를 놓치는 계획인지 살핀다. 합리적으로 구현 중 정할 세부 사항과 결과를 바꿀 미결정 사항을 구분한다.

## 반환

중요한 발견 사항에는 어떤 목적을 위태롭게 하는지, 문서·코드 근거와 실패 가능한 시나리오, 필요한 설계 수정을 적는다. 제품 결정이 필요하면 빠진 결정과 영향만 명확히 한다. 정해진 가정 수나 질문 형식을 통과 조건으로 사용하지 않는다.
