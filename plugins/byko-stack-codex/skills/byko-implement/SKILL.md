# 범위가 있는 구현

[작업 범위](../../shared/task-contract.md)를 따른다. 정식 설계 문서 없이도 충분히 구체적인 요청이면 구현할 수 있다.

## 현재 기준 확인

기대 동작·보존 동작과 실제 수정 경로를 확인한다. 저장소 지침, 인접 코드의 책임·의존 방향, 호출자·테스트를 필요한 만큼 읽는다. 기존 분석의 경로가 바뀌었거나 설계가 현재 계약과 충돌하면 원래 목적과 근거를 대조한다. 결과를 바꿀 미결정 사항은 구현으로 임의 확정하지 않는다.

인계된 요약을 완전한 맥락으로 가정하지 않는다. 실제 대상·중요한 원자료·인접 계약에서 맡은 변경이 의존하는 연결을 확인하고 요약에 없는 소비자·생명주기·데이터 상태 또는 흐름이 드러나면 영향을 살핀다. 유효한 근거를 재사용하며 전체 조사를 반복하지 않는다. 좁은 변경으로 충분한지는 확인한 관계·기대값·남은 공백으로 판단한다.

수정 전에 [검토 가안](../../shared/verification.md)의 기대 결과·근거·확인 방법을 이어받거나 필요한 범위에서 정한다. 기존 문서·테스트 또는 짧은 작업 기록이면 충분하며 이 준비 때문에 전체 설계 workflow를 요구하지 않는다.

## 구현

목적에 필요한 가장 단순한 변경을 한다. 기존 코드의 주 흐름이 읽히게 유지하고 중복 책임·불필요한 추상화·무관한 리팩터링을 피한다. 명시된 수정 범위를 지키며, 다른 작업자의 변경을 보존한다. 여러 writer가 있다고 추정해 일을 멈추지 않고 실제 충돌과 소유 범위를 확인한다.

변경에 관련된 오류·부분 실패·계약·저장 및 전송 형태를 처리한다. 현재 코드에 맞춰 요구사항을 축소하거나 테스트 정답을 바꾸지 않는다. 테스트·문서가 실제로 영향을 받으면 함께 맞추되, 모든 변경에 고정 산출물 세트를 만들지 않는다.

## 검증과 반환

기대 결과·보존 조건에서 검증을 도출한다. 필요한 검사와 작은 실행으로 정상·관련 실패·회귀를 확인한다. 저장·전송·UI 등 실제 결과가 드러나는 경계를 확인하고 mock 내부 성공만으로 완료하지 않는다. 실패가 기존 문제인지 필요한 경우 변경 전 기준과 비교한다.

기존 테스트·실행·검증 harness를 먼저 사용한다. 결과를 관찰할 방법이 부족하면 해당 공백만 보완하고 새로 만든 방법 자체를 실제로 실행한다. 시작·조작·관찰에 필요한 대상 버전·환경·권한·임시 자원의 소유와 정리를 확인한다. 테스트를 만들거나 실행 명령을 적은 것과 실제 관찰을 구분한다.

검증이 드러낸 범위 안의 문제를 수정하고 영향받은 부분을 다시 확인한다. 같은 전체 suite를 근거 없이 반복하지 않는다. 자신이 만든 임시 산출물과 제품 변경을 구분한다.

달성한 결과, 변경 파일, 검증 명령과 결과, 미검증·미완료 부분을 반환한다. 자체 확인은 독립 리뷰가 아니며 별도 reviewer가 없다는 이유로 구현 결과를 숨기거나 리뷰 통과를 만들어내지 않는다.

선택한 방법과 실제 변경의 차이, 새로 드러난 전제·보존 위험도 함께 반환한다. 설계 판단이 필요한 문제는 영향과 근거를 호출자에게 전달하며 전체 설계 workflow를 자동 재귀 호출하지 않는다. 허용된 공유 기록이 있으면 담당 범위를 갱신하고 별도 문서 세트는 만들지 않는다.
