# 사람이 이해할 수 있는 뷰어

[작업 범위](../../shared/task-contract.md)를 따른다. 기본 결과물은 **HTML**이다. 사용자가 다른 형식을 지정하면 그 형식을 따른다. 목적은 조사·분석된 정보를 사람이 빠르게 이해하고 머릿속에서 연결할 수 있는 뷰로 재구성하는 것이다. 일반 제품 UI 개발과 달리 전달할 내용의 설명 구조와 탐색 경험을 함께 책임진다.

## 무엇을 이해시킬지

독자, 읽는 이유, 이해하거나 결정할 내용, 사용할 근거를 요청과 자료에서 파악한다. 데이터 구조·조사 순서·원장 형식을 화면 구조로 복사하지 않는다. 독자가 무엇을 먼저 알아야 다음 내용을 이해하는지 판단하고, 전체 정보의 인과관계와 이해 순서를 먼저 설계한 뒤 화면을 만든다. 정보는 나열하지 않고 전체와 세부·원인과 결과가 연결되게 한다. 근거가 상관관계만 보여주면 인과관계로 단정하지 않는다. 별도 기획 문서나 사용자 승인 라운드를 필수로 만들지는 않는다.

첫 화면에서 주제와 의미, 핵심 메시지, 읽을 경로를 알 수 있게 한다. 독자가 이전 대화를 안다고 가정하지 않는다. 내부 용어·어색한 직역·업계 약어를 그대로 던지지 말고 쉬운 역할과 실제 의미를 먼저 설명한 뒤 정식 용어를 붙인다. 제품명·서비스명·재무지표·전문용어는 처음 보는 사람도 현재 위치에서 이해할 수 있게 설명한다. 다른 곳을 검색해야 이해되는 화면은 실패다. 예시 하나가 전체 구조에서 어디에 해당하는지 보여준다.

조사 내용 보존은 원문 복사가 아니다. 모든 중요한 사실·수치·조건·반론·한계·불확실성을 본문·시각화·표·상세 설명·근거 중 적절한 형태로 표현한다. 실제 데이터와 설명용 예시는 명확히 구분한다. 부족한 근거를 시각적으로 그럴듯하게 채우지 않는다.

## 설명과 화면

글은 여러 표현 수단 중 하나다. 관계·변화·크기·시간·비교·과정 등 정보의 성질에 맞춰 그림·도식·차트·타임라인·그래프·일러스트·표·인터랙션·동영상 등에서 가장 적절한 표현을 선택한다. 구조는 관계도, 시간 변화는 타임라인, 비교는 전후·나란히 보기처럼 실제 관계가 드러나게 한다. 모든 수단을 사용하라는 뜻은 아니며, 자료 성격에 필요한 시각 자료를 충분히 제공한다.

문장을 박스나 카드에 넣은 것만으로 시각화했다고 보지 않는다. 모든 내용을 동일한 카드·화살표·레이아웃으로 반복하지 않는다. 고정 템플릿을 여러 주제에 복제하지 말고 매번 데이터와 주제의 구조를 분석해 스토리와 표현 방식을 선택한다. 기존 자산을 활용해도 그 자산의 틀에 내용을 억지로 맞추지 않는다.

숫자도 사람이 체감할 수 있게 설명한다. 단위·기간·비교 기준·증감·규모를 드러내고 필요하면 통화 환산, 절대값과 증가율의 병기, 그래프 등을 사용한다. 환산·계산을 했다면 사용한 기준·시점·가정을 밝히고 원래 수치를 확인할 수 있게 한다. 비교 기준이 없으면 임의의 수치로 채우지 않는다.

## 정보 계층과 탐색

핵심 이야기 → 중요 근거 → 세부 설명 → 전체 원자료 순으로 중요도를 화면에 반영한다. 모든 정보를 같은 시각적 무게로 표시하지 않는다. 이 계층은 독자의 이해와 접근 경로에 대한 기준이며 고정 챕터 수나 화면 배치를 뜻하지 않는다.

요약에서 세부·근거로 들어가도 위치와 질문을 잃지 않게 한다. 긴 뷰에는 목차·현재 위치·검색·앞뒤 이동·근거 확인 후 복귀·모바일 탐색을 제공한다. 비교 대상이나 정의를 찾아 이동할 때 선택 상태와 관련 맥락을 유지한다. 고정 페이지 수·스크롤 방식·사이드바 유무를 모든 자료에 강제하지 않는다.

근거는 주장 가까이에서 찾을 수 있게 하되 긴 출처 메타데이터가 본문을 방해하지 않게 분리한다. 본문에는 짧은 출처 표시나 연결을 두고 상세·주석·근거 패널 등에서 원문 위치와 전체 원자료에 접근할 수 있게 한다. 제공된 자료의 공유·접근 범위를 지키며 없는 원자료나 링크를 만들어내지 않는다.

보충 정보는 필요할 때 펼치되 핵심 설명을 hover나 숨은 탭에만 두지 않는다. 탐색은 키보드·터치로도 가능하고, 색만으로 의미를 구분하지 않으며, 작은 화면·확대에서도 글·도표가 읽혀야 한다.

기존 UI·문서 자산이 있으면 적합한 부분을 활용한다. 형식 요청이 없는 설명 자료는 설치·서버 없이 열 수 있는 HTML을 우선한다. 공유에 필요한 자산을 함께 제공하고 로컬 절대경로나 외부 CDN에 기대어 깨지지 않게 한다. 실제 앱 연동이 목적이면 그 환경을 따른다.

## 확인과 전달

상호작용은 가능한 선택별로 설명 문구·시각 자료·선택 표시가 같은 사실과 상태를 나타내는지 확인한다. 정적인 순서도와 현재 상태를 보여주는 화면을 독자가 구별할 수 있게 한다.

HTML 구조 검사와 실제 화면 확인은 다르다. 브라우저 도구가 있으면 생성물을 열고 대표적인 넓은 화면과 좁은 화면에서 확인한다. 첫 화면 읽기, 목차·앞뒤 이동, 검색, 세부 열기, 근거 확인, 원래 위치 복귀 등 실제로 제공한 핵심 동작을 수행한다. 스크린샷으로 겹침·잘림·읽기 어려운 도표를 확인하고 고친다.

최종 성공 기준은 독자가 원자료를 읽지 않아도 핵심 구조와 의미를 이해하고, 궁금하면 그 자리에서 세부 설명과 근거까지 내려갈 수 있는 것이다. 이를 기준으로 화면의 주제·핵심 관계·결정할 내용을 설명할 수 있는지 자체 점검한다. 별도의 독자·검토자에게 확인받았다면 그 범위와 결과를 구분한다. 독립 검토자를 자동 생성하지 않는다.

결과물과 필요한 자산의 위치, 확인한 화면·상호작용, 남은 내용·사용성 공백을 전달한다. 브라우저를 쓸 수 없으면 가능한 정적 확인을 마치되 화면·사용성은 미검증으로 남긴다. 파일 생성만으로 전달 목적을 달성했다고 보고하지 않는다.
