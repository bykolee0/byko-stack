# 요청에서 확인된 결과까지

[공통 원칙](../../shared/workflow.md)을 읽고 적용한다. 이 스킬을 수행하는 메인이 요청 전체와 다음 행동을 소유한다. 전문 작업자에게 전체 진행 책임을 넘기지 않는다. 일반 요청의 진입점을 제공하지만 description만으로 모든 호스트의 암묵 호출을 보장하지 않는다.

## 요청과 현재 상태 복원

원문·후속 정정·기존 작업 자료·리포 지침과 현재 대상을 확인한다. 누가·언제·어디서·무엇을·어떻게·왜 원하는지 식별하고, 알고 싶은 것과 바꾸려는 것을 구분한다. 여기서 어떻게는 사용자·호출자 관점의 동작 조건이며 구현안을 뜻하지 않는다. 모르는 의도·정책을 채워 넣지 않으며 이미 확인한 목적과 권한을 다시 승인받지 않는다.

[산출물 관리](../../shared/artifacts.md)에 따라 기존 기록을 재사용한다. 인계 요약의 결론만 따르지 말고 맡은 판단이 의존하는 원문·현재 코드·인접 계약을 대조한다. 요약의 미확인 목록 밖에도 누락된 연결이 있을 수 있다. 피드백이 추가·예시·부분 수정·취소 중 무엇을 바꾸는지 기존 합의와 대조하고 영향받는 부분만 갱신한다.

## 기본 경로 실행

아래에서 맞는 플레이북을 **실제로 읽고 수행한다**. 스킬 호출은 연결된 `SKILL.md`를 읽고 해당 역할을 수행하는 뜻이며 가상의 slash-command 실행을 뜻하지 않는다.

| 요청한 결과 | 읽을 플레이북 |
|---|---|
| 제보·알람·의심되는 문제의 사건·원인·영향 확인 | [진단](../../playbooks/diagnosis.md) |
| 기능 개발·고도화 또는 근거가 확보된 수정 | [변경](../../playbooks/change.md) |
| 위 경로에 맞지 않는 조사·비교·계획·작업 | [수행 경로 구성](../../playbooks/compose.md) |

기본 단계를 현재 계획 도구 또는 작업 기록에 드러낸다. 도구가 없으면 짧은 진행 설명으로 충분하다. 읽었다는 보고가 실제 조사·위임·검증을 대신하지 않는다. 각 단계에 원문·목표·보존 조건·기준과 관련 근거를 전달하고 반환을 인수한 뒤 다음으로 간다.

조사 전에 제목·수정 줄 수·쉬워 보인다는 인상으로 경로를 줄이지 않는다. 원하는 결과의 출처, 관련 실행 경계와 계약, 남은 공백의 영향, 관찰 방법을 확인한 뒤 충분한 범위만 줄인다. 생략·통합한 행동과 충분성 근거를 짧게 남긴다. 접근 불가를 무관함으로 바꾸지 않으며 작은 고위험 변경의 검토를 삭제하지 않는다.

## 인수·복귀·완료

[오케스트레이션](../../shared/orchestration.md)에 따라 별도 질문·쓰기 범위·독립 판단이 필요한 작업을 구성한다. 고정 팀을 먼저 만들지 않는다. 반환의 대상·버전·조건을 맞추고 원래 질문, 목표, 보존 조건과 대조해 채택한다. 부분 작업 완료는 전체 완료가 아니다.

유효한 문제는 원인이 있는 조사·목표·방법·구현으로 돌려보내고 영향받는 판단만 다시 연다. 코드를 통과시키려고 기대값을 낮추지 않는다. 같은 지적과 시도가 새 근거 없이 반복되면 전제·접근·관찰 방법을 다시 판단한다. 직접 확인 가능한 사실은 조사하고 사용자만 결정할 의도·정책·범위가 남았을 때 필요한 질문을 한다.

요청한 결과의 실제 근거, 최종 대상 버전, 미검증·미완료와 다음 행동을 기록하고 반환한다. 진단 답변, 설계 검토, 로컬 검증, 대상 환경 확인, 외부 인계는 각각 확인한 범위대로 설명한다. PR·배포·게시·후처리는 요청과 리포 권한에 따르며 이 스킬이 추가 권한을 주지 않는다. 사용자가 native goal 사용을 명시적으로 요청했거나 기존 native goal이 있는 경우 해당 도구 계약을 따른다. 작업의 대목표를 정립하는 것만으로 native goal을 생성하지 않는다.
