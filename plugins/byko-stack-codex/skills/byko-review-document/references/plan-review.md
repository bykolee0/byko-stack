# 계획을 구현에 넘겨도 되는가

목표·요청과 현행 코드·관련 계약을 기준으로 계획이 실제 결과까지 이어지는지 판단한다. 파일 목록이나 작성자의 설명만 확인하지 말고 계획의 중요한 전제를 관련 호출자와 후속 경로에서 대조한다. 무관한 저장소 전체 조사를 요구하지 않는다.

인계 요약에 없던 관계와 리포 밖 의존성이 계획을 바꿀 수 있는지 살핀다. 데이터 자체와 흐름의 확인을 혼동하지 않고, 조사 축소에 실제 확인한 관계·기대값·남은 공백의 근거가 있는지 본다. 단계·작업자가 바뀌어도 기존 공유 자료를 갱신하며 불필요한 문서 세트를 만들지 않는지 확인한다.

제품 정책·사용자 동작·외부 계약·보존 조건·중요한 실패 처리에 영향을 주는 결정이 빠졌는지 본다. 구현자가 이를 조용히 선택해야 한다면 공백을 반환한다. 같은 계약을 충족하는 내부 선택은 구현자에게 맡길 수 있다. 상세한 제약은 정확성이 의존할 때 요구하며 취향·불필요한 구조 고정으로 계획을 과도하게 제한하지 않는다.

[사전 검토 기준](../../../shared/verification.md)을 적용한다. 요청·목표·현행 코드에서 나온 정상·반례·경계·보존·변경 영향 중 중요한 축과 관찰 방법이 있는지 확인한다. '구현 후 테스트 작성'이나 성공 반환만으로 실제 결과를 입증할 수 있는지 의심한다. 기대값의 출처와 사용자 결정이 필요한 부분을 구분한다.

기존 검증 경로를 확인하고 부족한 관찰 방법만 보완하는 계획인지 본다. 보완한 방법 자체의 실행, 실제 사용 접점의 조작·관찰, 임시 자원 소유와 정리, 대상 버전·환경의 근거가 필요한 만큼 포함되어야 한다. 설계 단계에서는 이 실행 계획의 충분성을 평가하며 아직 수행하지 않은 실행 결과를 요구하거나 통과로 만들지 않는다.

계획대로 수행해도 목표를 달성하지 못하는 조건을 찾고, 지적은 구체적 영향과 근거로 판단한다. 정상 계획에 무관한 정책·동시성·확장성 요구를 추가하여 반려하지 않는다. 계획 통과는 실행 검증 통과가 아니다.

문제가 계획의 누락인지 목표 해석의 오류인지 근거 조사 부족인지 구분해 반환한다. 이미 유효한 검토를 모두 초기화하지 않는다.
