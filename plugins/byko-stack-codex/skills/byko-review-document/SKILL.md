# 목적·논리·근거 검토

[검토 공통 기준](../../shared/review-principles.md)을 따른다. 파일 형식보다 지금 판단할 주장·설계·계획을 기준으로 읽는다.

## 목적과 근거

원래 요청·관련 계약과 문서를 대조한다. 요구사항과 보존할 동작이 빠지거나 수단 수행을 목적 달성으로 대신하지 않는지 확인한다. 사실·설계 선택·가정·미해결 사항이 구분되는지 본다.

문서의 핵심 전제가 의존하는 코드·원문·데이터를 허용된 범위에서 직접 확인한다. 출처가 결론을 실제로 뒷받침하는지, 서로 다른 시점·버전·집계 단위를 섞었는지 살핀다. 접근 불가능한 근거를 확인했다고 간주하지 않는다.

## 방법과 계획을 반증하기

제안대로 했는데도 목적을 이루지 못하는 입력·상태·사용 흐름을 찾는다. 구현·통합·실패 처리·호환성·운영 경계 중 관련된 공백을 확인한다. 계획은 파일 목록보다 작업을 모두 마쳤을 때 원하는 결과가 남는지로 평가한다.

중요한 계약과 의존 관계는 구체적이어야 한다. 합리적으로 구현 중 정할 세부 사항까지 미결정으로 취급하지 않는다. 아직 구현이 없는 설계에 실행 테스트 통과를 요구하지 않는다. 대신 계획된 검증이 실제 결과를 관찰할 수 있는지 확인한다.

## 반환

문제가 위태롭게 하는 목적, 근거 위치, 실패 가능한 상황과 보완 방향을 설명한다. 디자인 검토 통과와 실제 구현 검증은 구분한다. 자료를 읽기 어렵다는 문제는 정확성 문제와 구분하고, 사람용 화면의 이해·탐색까지 요청받았다면 사용 가능한 byko-review-viewer 지침을 함께 적용한다.
