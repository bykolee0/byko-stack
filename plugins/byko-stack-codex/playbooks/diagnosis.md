# 진단: 발생한 일과 실제 결과를 설명하기

이 플레이북은 [byko-work](../skills/byko-work/SKILL.md)를 수행하는 메인이 실행한다. 제보·알람 자체를 결함 확정이나 수정 권한으로 읽지 않는다. 아래 연결의 스킬·공통 지침을 해당 단계에서 읽고 수행한다.

## 1. 질문과 근거 조사

원문·정정에서 알고 싶은 사건·원인·영향과 대상·기간·환경을 확인한다. 기대 동작의 출처, 관찰된 증상, 현재 가설을 구분한다. [byko-analyze](../skills/byko-analyze/SKILL.md)에 원문·목표·범위·관련 근거를 전달해 조사한다. 서로 다른 근거 영역의 독립 질문은 [분리 조사](../shared/orchestration.md#분리-조사와-종합)로 맡긴다.

실제 입력·처리·후속 결과와 결론이 의존하는 연결을 따라간다. 정책·코드·컨벤션·데이터 상태·데이터 흐름은 관련성을 확인할 관점이며 조사 범위의 상한이 아니다. A의 원인·수명·결과가 B에 의존하면 허용 범위에서 리포·인프라·외부 자료의 B까지 확인한다.

반환의 사실·추론·미확인을 구별하고 대상·조건·시점을 맞춰 인수한다. 중요한 관계를 보기 전에 모호함을 사용자 선택으로 넘기지 않는다. 접근하지 못한 근거는 미확인으로 남긴다.

## 2. 가설을 구별하고 독립 반증

허용된 테스트 환경에서 원래 조건을 재현하거나 경쟁 설명을 구별할 관찰을 수행한다. 부작용이 있는 실행은 권한을 확인하며 진단 요청을 데이터 변경·외부 전송 권한으로 확대하지 않는다. 재현되지 않으면 환경·조건 차이와 운영 흔적을 대조한다. 재현 실패는 결함 부재나 조사 포기의 근거가 아니다.

원인·영향을 판단하는 진단은 [가설·결론 반증](../shared/orchestration.md#가설과-결론-반증)을 기본으로 수행한다. [byko-review](../skills/byko-review/SKILL.md)에 원문·목표·질문별 기준·현재 대상과 근거를 주고, 조사 충분성·경쟁 설명·실제 영향·회복 판단을 독립 확인한다. 조사 종료의 전제도 검토 대상이다. 검토자 동의 수로 입증하지 않는다.

단일 원자료의 값·문장 확인만 요청했고 인과·영향 추론이 없으며 그 원자료로 질문이 해소된다는 근거가 있으면 직접 확인으로 줄일 수 있다. 축소 이유와 확인 범위를 짧게 남긴다. “간단한 알람”이라는 인상은 축소 근거가 아니다. 독립 검토가 불가능하면 자체 점검은 수행하되 독립 미검증을 밝힌다.

## 3. 질문별 결과 인수

사건 발생, 원인 입증 수준, 최종 사용자 영향, 현재 회복과 미확인을 각각 대조한다. 시도 실패와 최종 요청 실패, 재시도 접수와 실제 후속 완료는 다르다. 인접한 성공을 특정 실패의 회복 증거로 사용하지 않는다.

유효한 지적은 관련 조사·관찰·해석으로 돌려보내고 새 근거로 해당 판단을 갱신한다. 정상 동작·이미 해결됨·증거 부족도 근거에 맞는 결론이 될 수 있다. 피해 규모·원인 확정·정상 판정을 억지로 만들지 않는다.

## 4. 요청 범위에 맞게 설명 또는 변경

진단만 요청했다면 확인한 사건·원인·영향·회복·한계와 질문 해소 여부를 설명하고 마친다. 중요한 영향은 원인 확정 전에도 확인 수준과 함께 전달할 수 있다.

수정까지 요청받았고 변경 필요성과 근거가 확보됐으면 수정 목표·보존·관찰 기준을 구체화해 [변경](change.md)을 읽고 이어간다. 통상적인 수정 진행을 다시 승인받지 않는다. 이후 수정 요청이 추가됐다면 요청 범위를 갱신하고 기존 근거의 시점·버전·환경부터 대조한다. 정상 동작을 바꾸려는 요청은 새 동작 목표로 다룬다.

향후 재발 방지와 과거 데이터·이미 발생한 영향의 해소는 구별한다. 백필·복구·이슈 종료·외부 공유를 진단에 자동 포함하지 않는다. 기존 공유 자료를 갱신하되 진단만 요청한 작업에 제품 파일 변경이나 문서세트를 요구하지 않는다.
