# 알려진 플레이북 밖의 수행 경로 구성

[byko-work](../skills/byko-work/SKILL.md)를 수행하는 메인이 원하는 결과·현재 상태·허용 변경·관찰 기준을 먼저 확인한다. Feature/Fix로 억지 분류하거나 새 플레이북 파일부터 만들지 않는다. 계획만 요청받으면 실행까지 확장하지 않는다.

## 기본 연결

1. **판단에 필요한 근거:** [byko-analyze](../skills/byko-analyze/SKILL.md)를 읽고 원문·목표·범위와 현재 자료를 전달한다. 결론이 의존하는 연결과 실제 상태를 확인하고 다음 판단에 필요한 공백을 인수한다.
2. **방법과 성공 기준:** 목표·보존·관찰 기준이 부족하면 [byko-design](../skills/byko-design/SKILL.md)을 읽고 구체화한다. 방법 후보만 필요하면 [byko-propose](../skills/byko-propose/SKILL.md)를 읽고 작성한다. 현재 상태와 비교할 baseline, 가설 또는 변경, 성공·실패를 구별할 관찰을 정한다.
3. **범위 안의 수행:** 분석·구현·뷰어 제작 등 필요한 전문 스킬을 읽고 해당 단위만 수행한다. 독립 질문·후보·쓰기 경계가 있으면 [오케스트레이션](../shared/orchestration.md)을 읽고 구성한다. 조율 비용을 정당화할 근거 없이 고정 팀을 만들지 않는다.
4. **관찰과 독립 판단:** 결과와 기준을 대조하고 [byko-review](../skills/byko-review/SKILL.md)를 읽어 해당 목표·방법·주장·변경을 독립 검토한다. 단일 원자료 조회로 충분한 경우는 진단 플레이북의 축소 조건을 적용할 수 있다. 자체 확인과 독립 판정을 구별한다.
5. **인수와 다음 행동:** 목표에 기여한 결과·새 근거·남은 공백을 인수한다. 충족이면 요청한 결과를 반환하고, 부족하면 영향받는 조사·방법·수행으로 돌아간다. 새 근거 없는 반복은 전제·관찰법을 재검토하며 접근·사용자 결정이 필요한 실제 경계를 설명한다.

기존에 충분한 기준·결과가 있으면 재사용하고 어떤 행동을 생략·통합했는지 근거를 남긴다. 여러 능력을 조합한다는 이유로 전체 설계·개발을 모든 요청에 강제하지 않는다. 권한 없는 백필·운영 복구·외부 게시를 자동 실행하지 않으며 별도 무기한 loop나 native goal을 자동 생성하지 않는다. 현재 공유 기록을 갱신하고 계획·실행·확인한 결과를 구분해 반환한다.
