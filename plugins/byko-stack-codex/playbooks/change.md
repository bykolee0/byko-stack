# 변경: 원하는 동작과 보존할 계약을 함께 확인하기

[byko-work](../skills/byko-work/SKILL.md)를 수행하는 메인이 실행한다. 기능 개발·고도화와 근거가 확보된 수정이 이 경로를 공유한다. 각 단계의 연결된 스킬을 읽고 실제로 수행하며 반환을 원래 목표·보존 조건과 대조한다.

## 1. 현재 기준과 목표·방법

원문·정정·현재 대상과 기존 분석을 대조한다. 진단에서 왔다면 전체 조사를 반복하지 말고 변경 판단에 필요한 공백을 채운다. [byko-analyze](../skills/byko-analyze/SKILL.md)로 현행 동작·정책·컨벤션·관련 데이터와 흐름·인접 계약을 확인한다. 요약 밖의 연결도 결과에 영향을 주는지 살핀다.

[byko-design](../skills/byko-design/SKILL.md)을 읽고 원문·목표·근거·권한·현재 버전을 전달한다. 바뀔 동작, 보존할 계약, 기대값 출처와 관찰 방법을 구현 전에 정한다. 목표 검토 → 방법·계획 → 계획 검토를 수행하며 유효한 기존 기준과 검토는 재사용한다. 함께 준비된 목표·계획은 한 검토에서 두 판단을 구별할 수 있다.

메인은 준비된 목표·방법·검증 기준과 독립 판정의 범위를 인수한다. 단순 문서 존재나 이전 통과 표시를 현재 기준의 유효성으로 보지 않는다. 미결정 정책을 구현자에게 떠넘기지 않는다.

## 2. 구현과 자체 확인

[byko-implement](../skills/byko-implement/SKILL.md)를 읽고 수행한다. 분리된 쓰기 범위가 있으면 [분리 구현](../shared/orchestration.md#분리-구현과-통합)에 따라 위임한다. 목표·선택안·보존 조건·사전 기준·원자료·쓰기 범위를 전달한다. 조사로 좁고 명확함이 확인된 수정은 메인이 직접 수행할 수 있다.

구현자는 현재 코드·컨벤션·인접 계약을 대조하며 요약을 구현 명령으로만 취급하지 않는다. 설계와 실제가 충돌하면 차이·근거·영향을 반환한다. 메인은 코드 문제는 구현으로, 설계 전제 문제는 `byko-design`의 관련 판단으로 돌려 기준과 코드를 맞춘다.

반환된 실제 변경·자체 검증·미확인을 인수하고, 단위별 통과에 없는 통합 경계를 확인한다. 새 위험은 검증 기준에 추가하되 구현에 맞춰 기대값을 완화하지 않는다.

## 3. 독립 검토와 재작업

[byko-review](../skills/byko-review/SKILL.md)를 읽고 원문·목표·보존·사전 기준, 현재 수정본과 실제 실행 근거를 전달한다. 규모를 이유로 독립 검토를 없애지 말고 실제 영향에 맞게 범위를 좁힌다. 별도 실패 질문이 있을 때만 검토자를 나눈다.

메인은 유효한 지적을 사실·반례와 대조해 조사·설계·구현의 해당 책임으로 돌린다. 수정 후 finding 해소와 영향받는 계약을 재검증·재검토한다. 이전 버전의 판정을 새 수정본의 통과로 재사용하지 않는다. 이미 확인한 무관한 광역 검사는 반복하지 않는다.

목적·문제 해소·보존에 대한 관찰을 대조한다. 리뷰어가 문제를 찾지 못했거나 mock·CI가 통과한 사실만으로 실제 결과를 판정하지 않는다. 독립 기능이나 중요한 실행 환경이 없으면 그 공백을 미검증으로 남긴다.

## 4. 대상 환경과 인계

사전 기준에서 필요한 사용자·호출자 접점과 저장·전송·후속 효과를 실제로 확인한다. 기존 harness를 우선 사용하고 관찰 방법을 보완했다면 그 방법도 실행해 유효성을 확인한다. 로컬·통합·대상 환경, 최종 수정본·배포본의 차이를 구별한다.

PR·배포·게시·머지는 리포 계약과 요청 권한에 따르며 무조건 dev 배포로 끝내지 않는다. 필수 확인이 막혔다면 확인한 결과·남은 조건·정확한 재개 지점을 남긴다. 공유 자료를 갱신하고 요청한 결과의 실제 달성 근거와 중요한 미검증을 반환한다.
