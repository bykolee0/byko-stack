# 공유 산출물과 작업 재개

## 기존 자료를 함께 갱신하기

사용자가 지정한 이슈·문서·경로와 현재 대화의 작업을 먼저 사용한다. 없으면 관련 기존 자료를 찾아 이어받는다. 저장소의 경로·형식·CI 계약을 지키며 기존 산출물을 일괄 이관하거나 과거 이력을 덮어쓰지 않는다. 서로 다른 작업을 실제로 구분할 수 없을 때만 질문한다.

지속적인 작업 기록이 필요하고 기존 위치가 없으면 `docs/work/<작업명>/index.md` 하나에서 시작한다. 요청한 진단·설계·변경의 이름을 사용하며 모든 일을 spec으로 분류하지 않는다. 단순 조회·일회 응답·단독 전문 작업에 파일 저장을 요구하지 않는다. 문서 수를 줄이더라도 목표·보존 조건·검증 근거를 삭제하지 않는다.

단계나 에이전트가 바뀌어도 기존 자료를 공유하고 갱신한다. 상태를 관리하는 위치는 하나를 정해 명시하며 기존 manifest·goal·이슈 관리 체계가 있으면 활용한다. 단계별 요청서·분석서·계획서·검증서 세트를 새로 만들지 않는다. 리포가 여러 파일의 갱신을 계약으로 요구하면 그 계약은 지킨다.

## 담아야 할 정보와 분리 조건

정보의 역할은 다음과 같으며 별도 파일이나 고정 제목을 뜻하지 않는다.

| 정보 | 판단과 재개에 필요한 내용 |
|---|---|
| 요청과 목적 | 원문·정정의 출처, 유효한 합의, 적용 조건·요구사항·보존 조건·관찰 가능한 달성 조건, 사용자가 요청한 수행 범위 |
| 분석과 근거 | 실제 대상·버전·기간·환경, 확인한 관계, 중요한 주장과 출처, 가정·경합 설명·남은 공백 |
| 방법과 결정 | 선택한 접근·이유·다른 선택의 단점, 필요한 계약·실패 처리·의존 순서, 변경이 판단에 미친 영향 |
| 검증과 검토 | 변경 전 기대값과 확인 방법, 실제 관찰값·대상 버전·환경, finding·해소 근거, 자체/독립/대상 환경 확인의 구분 |
| 현재 상태 | 완료·진행·남은 일, 필요한 결정·접근, 다음 행동과 재확인할 근거 |

목적에서는 누가·언제·어디서·무엇을·어떻게·왜를 식별할 수 있게 한다. 여섯 관점은 사용자 설문이나 구현 구조를 채우는 칸이 아니다. 원문·확인된 사실·해석·제안을 구분하고 목표만 요청받았다면 방법·구현까지 확장하지 않는다.

자료가 길어 읽기 어렵거나 독립적인 조사·검토·갱신 책임이 실제로 필요할 때만 나눈다. 분야마다 기계적으로 파일을 만들지 않고 함께 판단할 내용을 묶는다. index에는 본문을 다시 요약해 복제하기보다 현재 판단과 필요한 자료의 연결을 둔다. 링크에는 어떤 판단이 어떤 근거에 의존하는지 드러낸다. 짧은 작업은 한 파일이나 기존 이슈 본문으로 충분하다.

## 소유권·정정·검토 유효성

메인은 목표·합의·index·종합 판단을 관리한다. 작업자는 배정된 영역을 갱신하거나 결과를 반환하며 동일 파일의 writer가 겹치면 순차 수행한다. 작업자별 영구 보고서를 만들 필요는 없다. 의미 있는 결정·결과·중단에 갱신하며 모든 도구 호출을 원장으로 남기지 않는다.

새 피드백이 바꾼 부분과 유지되는 합의를 구분한다. 중요한 결론이 바뀌면 현재 결론·변경 이유·영향을 남기고 이전 판단을 현재 결론과 혼동하지 않게 한다. 유효한 원자료와 중요한 반론·한계는 보존하되 문서 여러 곳에 진행 상태를 중복 기록하지 않는다.

검토에는 commit과 working diff, 관련 파일 hash 등 대상·버전을 구별할 근거를 남긴다. 시간이나 ‘통과’ 표시만으로는 충분하지 않다. 변경이 생기면 무엇이 무효화됐는지 판단하고 관련 기준·문서·구현·검증을 갱신한다. 무관한 검증은 유지한다. 문서 검토 통과와 실행 결과를 구분한다.

## 인계와 재개

index·요약에서 원래 요청·목표·합의·관련 근거를 따라간다. 실제 branch/diff·현재 파일·환경과 기록을 대조해 완료 표시·전제·검토 근거가 여전히 유효한지 확인한다. 요약에서 빠진 관계가 있을 수 있으므로 맡은 판단이 의존하는 현재 호출자·소비자·생명주기 등도 살핀다. 미확인 목록을 조사 상한으로 삼지 않는다.

기존 근거가 충분하면 활용하고 바뀐 버전·환경·새 질문·누락된 연결만 보완한다. 진단 후 수정 요청이 추가되면 사용자가 요청한 수행 범위와 변경 목표를 갱신하고 기존 진단의 시점·대상 유효성을 확인한다. 단순히 문서를 읽었거나 인덱스에 등록됐다는 사실로 인계 완료를 판단하지 않는다.

## 독자별 전달

외부 이슈·협업 공간과 리포는 독자와 접근 조건이 다르다. 허용된 갱신에서는 그 독자가 이해할 상황·결론·근거·한계를 본문에 충분히 제공한다. 접근할 수 없는 로컬 파일 링크만으로 설명을 대신하지 않는다. 외부 게시 권한은 요청·기존 승인에서 확인하며 이 문서가 권한을 추가하지 않는다.

단독 리뷰는 응답으로 결과를 제공한다. 저장소 보고서·상태 갱신은 요청됐거나 맡은 workflow의 허용 범위일 때만 한다. 설명용 뷰어는 원자료와 연결하고 별도의 진행 상태 정본으로 만들지 않는다.
