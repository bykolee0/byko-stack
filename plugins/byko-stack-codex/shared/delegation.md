# 번들 역할로 작업 위임하기

역할 정의는 이 문서와 같은 플러그인의 `../agents/`에 있다. 사용자 native agent 등록이나 원본 Git checkout을 요구하지 않는다. 현재 읽은 스킬·이 문서의 실제 위치를 기준으로 경로를 해석하며, 작업 repo의 cwd나 예전 cache 경로를 플러그인 루트로 쓰지 않는다.

## 직접 수행과 위임

요청과 현재 근거에서 다음 판단을 바꿀 불확실성·조사 질문을 먼저 찾는다. 초기 해석은 조사 방향을 정하는 가설이며 확정된 사용자 요구로 넘기지 않는다. 독립 질문, 경계가 분리된 구현, 설명 자료 제작처럼 별도 컨텍스트의 이점이 있는 일은 아래 역할에 위임한다. 이 지침은 해당 위임을 명시적으로 요청한다. 작은 조회·수정은 같은 전문 스킬을 직접 적용해도 된다.

페르소나는 이번 질문에 필요한 관점과 책임으로 구성한다. 추가 전문 관점 없이 기본 역할로 충분할 수도 있다. 역할 이름을 먼저 정하고 일을 끼워 넣거나 최소 인원·고정 팀을 요구하지 않는다. 여러 agent가 필요하면 서로 확인할 질문·근거·소유 범위를 구별하고, 새 결과에 따라 구성을 조정한다. 단독 전문 스킬은 이 workflow를 다시 호출할 필요가 없다.

| 맡길 일 | TOML | 전문 스킬 |
|---|---|---|
| 근거 조사 | [byko-analyst](../agents/byko-analyst.toml) | [분석](../skills/byko-analyze/SKILL.md) |
| 목표·보존 기준에 맞는 방법 후보 작성 | [byko-designer](../agents/byko-designer.toml) | [제안](../skills/byko-propose/SKILL.md). 전체 설계·검토 조율을 다시 호출하지 않음 |
| 범위가 정해진 구현 | [byko-implementer](../agents/byko-implementer.toml) | [구현](../skills/byko-implement/SKILL.md) |
| 독립 검토 | [byko-reviewer](../agents/byko-reviewer.toml) | [코드](../skills/byko-review-code/SKILL.md)·[문서](../skills/byko-review-document/SKILL.md)·[뷰어](../skills/byko-review-viewer/SKILL.md) 중 필요한 것 |
| 사람용 자료 제작 | [byko-viewer](../agents/byko-viewer.toml) | [뷰어 제작](../skills/byko-build-viewer/SKILL.md) |

## 생성에 설정 적용

TOML에서 `model`, `model_reasoning_effort`, `developer_instructions`를 읽는다. Python 3.11 이상을 사용할 수 있으면 [prepare_agent.py](../scripts/prepare_agent.py)를 실행해 설정과 현재 패키지의 전문 스킬 경로를 얻을 수 있다.

```sh
python3 "<설치된 플러그인 루트>/scripts/prepare_agent.py" byko-reviewer
```

출력의 `model`과 `reasoning_effort`는 생성 도구의 실제 설정 인자에, `message`는 역할 지침으로 전달한다. 이번에 답할 질문과 필요한 관점, 원래 요청·정정·근거 위치, 허용·제외 범위, 판단에 필요한 반환 근거를 작업 메시지에 덧붙인다. 아직 목표를 정립하는 조사라면 확정 목표가 있다고 가정하지 않는다. 긴 원문·공통 스킬을 반복 복사하거나 고정 입력 양식·요청서 파일을 만들 필요는 없다. helper가 없거나 Python이 맞지 않으면 TOML과 위 경로를 직접 읽어 같은 내용을 구성한다. 파일 누락·오류를 무시하고 기본 모델로 생성하지 않는다.

먼저 현재 호스트가 공개한 생성·메시지·대기·중단 도구와 인자를 확인한다. 같은 Codex라도 이 세션과 별도 CLI의 도구 이름·지원 인자가 같다고 가정하지 않는다. `spawn_agent`에 `model`, `reasoning_effort`, `fork_turns`가 있으면 해당 인자를 사용하되, 없는 인자를 만들어 전달하지 않는다. `role`은 식별용 메타데이터이며 등록되지 않은 `agent_type`으로 넘기지 않는다. helper는 생성 요청 준비일 뿐 실행·등록·권한 적용을 수행하지 않는다.

full-history fork가 모델·노력 수준 변경을 막는 도구라면 새 컨텍스트를 선택한다. 최초 독립 reviewer와 독립 후보 작성자에는 원래 요청·대상·원본 근거·사전 검토 기준을 주고 작성자의 예상 판정·다른 reviewer나 후보의 결론·전체 구현 대화를 전달하지 않는다. 사전 기준과 객관적인 위험 근거는 제외하지 않는다. 현재 도구가 `fork_turns`를 지원하면 이 독립 작업에는 `none`을 사용한다. 새로운 컨텍스트라도 공유 파일 접근까지 격리된 것은 아니다.

생성 요청과 도구가 반환하는 실행 설정을 확인한다. 도구가 실제 적용값을 노출하지 않으면 확인한 것은 요청 설정까지임을 구분한다. TOML 내용을 메시지에 적는 것만으로 모델·권한이 적용되었다고 보지 않는다. native 개발자 지침과 작업 메시지의 우선순위도 동일하다고 주장하지 않는다.

## 범위와 결과 통합

상세 맥락은 agent가 직접 찾을 수 있게 원본 위치로 전달한다. 코드만 조사하는 범위, write 소유권, 보존할 계약은 빠뜨리지 않는다. 독립 writer의 파일·공유 상태가 겹치면 순차 수행한다. 같은 질문을 여러 agent가 반복 조사하거나 여러 실행자가 같은 광역 검사를 돌리게 하지 않는다.

위임에는 원래 요청·정정·대목표·유효한 합의, 맡은 질문의 기여, 사용자가 요청한 수행 범위·허용 범위, 원자료의 위치·버전·환경, 확인한 관계·남은 공백, 기대 결과·보존·관찰 기준을 포함한다. 필요한 정보만 자연어와 링크로 전달하며 고정 요청서 파일은 만들지 않는다. 수신자는 [작업 계약](task-contract.md)에 따라 현재 대상과 중요한 전제를 직접 확인하고 요약에 없는 관련 연결도 살핀다. 메인은 역할 사이에서 중요한 질문이 빠지지 않았는지 확인한다.

반환된 답·변경 파일·검증 근거·남은 문제를 원래 목표·기준과 대조해 통합한다. 사실·추론·미확인, 대상 버전·환경, 새 의존 관계와 충돌을 구분한다. 구현자의 자체 검증은 독립 리뷰를 대신하지 않는다. 독립 검토의 시작과 결과 통합은 [byko-review](../skills/byko-review/SKILL.md), 목적·방법이 바뀌는 판단은 [byko-design](../skills/byko-design/SKILL.md)이 맡는다. 유효한 발견 사항은 수정한 뒤 영향받은 부분을 재확인한다. 전문 작업자는 결과와 재수행 범위를 반환하며 조율 스킬을 역호출하지 않는다.

분석 결과도 출처·누락·상충을 확인한다. 부족하면 충족하지 못한 질문, 실제 차이와 근거, 다시 확인할 범위를 구체적으로 전달한다. 결과 전체를 같은 말로 다시 만들게 하지 않는다. 재수행 결과가 해당 문제를 해소했는지 확인하고, 새 근거 없이 같은 주장만 반복되면 자료·접근·사용자 결정 중 무엇이 부족한지 밝힌다. 조사로 해결할 수 없는 의도·정책만 사용자에게 묻고 그에 의존하지 않는 일은 계속한다.

## 실행 회수와 기능 제한

작업자가 실패·미응답이면 회수 가능한 근거와 미확인 범위를 보존한다. 현재 호스트의 상태·메시지·대기·중단 도구를 사용해 실행 상태와 쓰기 소유권을 확인한 뒤 좁게 재지시하거나 직접 수행한다. 예를 들어 `send_message`, `followup_task`, `interrupt_agent`가 노출됐을 때 그 도구 계약을 따른다. 이름이 같은 도구가 있다고 가정하지 않는다. 중단을 확인할 수 없으면 같은 대상에 겹쳐 쓰지 않는다. 늦게 도착한 결과는 현재 버전·판단과 대조한 뒤 채택한다.

현재 정책·도구·모델 지원을 먼저 확인한다. 기능 부재나 지속되는 같은 오류를 새 프로세스·외부 모델로 우회하지 않는다. 사용 가능한 전문 스킬로 현재 세션에서 가능한 작업을 수행하고, 위임·요청 설정·독립성 중 확보하지 못한 것을 결과에 명시한다. 독립 리뷰가 필요한 완료는 `미검증`으로 남긴다. 다른 모델을 조용히 선택하거나 생성 실패를 작업 완료로 보고하지 않는다.
