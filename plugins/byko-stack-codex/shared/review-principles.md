# 검토의 공통 기준

[작업 범위](task-contract.md)를 따른다. 원래 요청·보존 계약·관련 근거에서 기대 결과를 도출하고 현재 산출물과 대조한다. 구현과 그 테스트가 같은 주장을 한다는 사실만으로 올바르다고 판단하지 않는다.

검토 대상은 수정하지 않는다. 허용된 테스트·작은 임시 재현으로 확인하며, live 데이터나 외부 상태를 바꾸지 않는다. 이미 다른 실행자가 수행한 검사에 대상 버전과 충분한 근거가 있으면 활용하고, 자기 finding에 필요한 재현만 추가한다.

독립 검토에서는 작성자의 예상 결론·이전 리뷰 판정을 먼저 읽지 않는다. 이미 그런 정보를 본 경우 검토를 계속할 수 있지만 독립성을 주장하지 않는다. 이 지침은 검토자를 생성하는 workflow가 아니다. 맡은 범위를 직접 검토하고 결과를 반환한다.

발견 사항에는 기대 결과, 실제 차이, 근거 위치, 구체적인 영향과 수정 방향을 남긴다. 재현하지 못했어도 경로상 입증되는 문제는 그 근거를 설명한다. 가능성만 있는 위험은 미검증과 구분하고 취향·범위 밖 개선을 blocking 문제로 올리지 않는다.

판정은 **통과 / 수정 필요 / 미검증**으로 전달한다. 중요한 문제가 확인되면 수정 필요이며, 함께 남은 검증 공백도 적는다. 문제를 발견하지 못했어도 핵심 결과의 근거가 없으면 미검증이다. 통과는 대상·버전·검토 범위에 한정한다. 파일 hash, commit과 diff 등 변경을 구별할 근거를 남기며 문서 검토와 구현·운영 검증을 혼동하지 않는다.

새 근거 없는 반복 탐색으로 검토를 늘리지 않는다. 영향이 작은 정적 변경에 무관한 실행 환경을 요구하지 않고, 필요한 실행을 못 했다면 그 경계만 정확히 남긴다.
