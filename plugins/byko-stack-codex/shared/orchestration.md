# 작업 구성과 결과 인수

플레이북 또는 설계·검토 호출자가 다음 판단을 바꿀 질문과 실제 경계를 정해 사용한다. 같은 기본 팀을 모든 작업에 배치하지 않는다. 이 문서는 아래 조건에 해당하는 독립 agent 위임을 명시적으로 요청한다. 전문 스킬로 위임받은 작업자는 다시 팀을 생성하지 않고 맡은 결과를 반환한다.

## 공통 실행 계약

[위임 지침](delegation.md)을 읽고 번들 TOML·`prepare_agent.py`가 반환한 역할 설정과 전문 스킬 경로를 사용한다. 현재 호스트의 실제 생성 도구와 지원 인자만 사용한다. `collaboration.spawn_agent`가 있으면 독립 reviewer와 후보 작성자는 `fork_turns="none"`으로 생성하고 허용된 `model`, `reasoning_effort`, `message`를 적용한다. 지원하지 않는 `agent_type`이나 Claude 전용 workflow 실행기를 가정하지 않는다.

입력에는 원문·정정·대목표, 맡은 질문이 목표에 기여하는 부분, 요청 범위·권한, 보존·사전 기준, 원자료 위치와 버전·환경, 알려진 관계·공백, 쓰기 소유권과 기대 반환을 포함한다. 자연어·링크면 충분하며 별도 요청서 파일은 필요 없다. 수신자는 요약을 길잡이로 삼고 중요한 전제와 실제 인접 관계를 확인한다. 요약의 공백 목록만으로 조사 범위를 닫지 않는다.

반환에는 답·실제 변경, 확인된 사실과 해석, 대상·조건·버전별 근거, 기준 충족·미확인, 새 연결·불일치를 담는다. 호출자는 원문·목표·보존과 대조해 채택하고 상충·공백을 다음 판단에 연결한다. 완료 문구나 동의 수로 인수하지 않는다. 공유 기록은 [산출물 관리](artifacts.md)에 따라 갱신하며 같은 파일의 writer는 순차 수행한다.

## 분리 조사와 종합

서로 다른 근거 영역에서 독립적으로 답할 질문이 있으면 `byko-analyst`에게 나눠 맡긴다. 같은 조사를 복제하지 않는다. 한 경로와 기존 근거로 충분함이 확인되면 메인이 분석 스킬을 직접 적용한다.

각 조사자는 질문별 사실·추론·근거·남은 연결을 반환한다. 호출자는 기간·버전·조건을 맞춰 종합하고 모순과 누락만 추가 조사한다. A의 의미·영향이 B에 의존한다면 담당 분할 사이에서 B가 빠지지 않았는지 확인한다. 하나의 요약에서 나온 여러 의견은 독립 증거가 아니다.

## 가설과 결론 반증

원인·실제 영향 판단의 진단에서는 기본으로 [byko-review](../skills/byko-review/SKILL.md)를 호출해 조사 충분성과 설명을 독립 반증한다. 서로 경합하는 가설이 있으면 각각 예측하는 관찰, 지지·반박 근거와 구별 가능한 확인을 전달한다. 인과 주장 없이 단일 원자료 조회만으로 충분한 경우의 축소는 [진단](../playbooks/diagnosis.md)을 따른다.

reviewer는 원문·관찰에서 설명이 성립하는지, 대안·누락 연결·회복 근거가 결론을 바꾸는지 확인한다. 작성자의 예상 판정이나 다른 reviewer의 답은 최초 입력에서 제외하되 원래 기준과 객관적인 위험 근거는 전달한다. 호출자는 독립 지적의 근거를 대조하고 잘못된 가설·영향 추론을 수정한다. 실행 불가를 반증 통과로 세지 않는다.

## 후보 작성과 비교

조사 결과 중요한 방법 선택이 남고 서로 다른 접근이 실제로 성립하면 `byko-designer`와 [byko-propose](../skills/byko-propose/SKILL.md)를 사용해 독립 후보를 작성한다. 같은 목표·보존·검증 기준을 주고 서로의 답을 읽지 않도록 한다. 숫자를 채우기 위한 대안을 만들지 않는다. 제약과 근거가 방법을 한정한다면 직접 후보를 작성하고 그 충분성 근거를 남긴다.

후보 작성자는 방법·근거·단점·실패 조건·검증 접근을 반환한다. [byko-review](../skills/byko-review/SKILL.md)로 필수 기준 충족과 전제를 확인한 뒤 호출자가 차이·비용·실패 영향을 종합해 선택한다. 모두 탈락할 수 있다. 후보를 합치면 통합본도 기준과 대조하며 각 후보의 통과를 통합본 통과로 옮기지 않는다. 후보가 많아 비교를 줄일 실제 이유가 있을 때만 토너먼트를 사용한다.

## 독립 검토와 재작업

[byko-review](../skills/byko-review/SKILL.md)의 기본 reviewer를 사용한다. 서로 다른 중요한 실패 질문이 있으면 관점·근거를 나누며 고정 인원이나 페르소나를 요구하지 않는다. 원문·목표·사전 기준·현재 대상과 버전을 전달하고 광역 검사는 한 실행자가 소유한다.

유효한 finding은 차이·근거·해소 조건과 함께 조사·목표·방법·구현 중 원인이 있는 수행자에게 반환한다. 수정 후에는 해당 finding과 영향받는 계약을 확인한다. 같은 지적·수정이 새 근거 없이 반복되면 전제·관찰법을 재판단한다. 지적 부재, 테스트 개수, 다수결은 완료 조건이 아니다.

## 분리 구현과 통합

구현 단위의 쓰기 범위가 분리되고 선행 의존이 준비됐으면 `byko-implementer`에게 목표·선택안·보존·기준·파일 소유권을 전달한다. 공유 파일이나 실행 환경이 충돌하면 순차 수행한다. 좁은 수정은 확인된 경계에 따라 메인이 직접 수행할 수 있다.

단위 변경·실행 결과·설계 차이·미검증을 인수한 뒤 통합된 수정본과 실제 경계를 검증하고 독립 리뷰한다. 단위별 통과만으로 전체 동작을 통과시키지 않는다.

## 미응답·실패·늦은 반환

현재 도구의 상태 조회·대기 기능으로 실행과 쓰기 소유권을 확인한다. `send_message`는 진행 중 질문·범위 정정, `followup_task`는 반환 후 한정 재작업에 사용한다. 필요하면 `interrupt_agent`로 중단을 요청하고 실제 상태를 확인한 뒤 회수한다. 도구가 다른 호스트에서는 대응하는 지원 기능만 사용한다.

중단을 확인할 수 없는 writer와 겹치는 변경을 새로 맡기지 않는다. 회수 가능한 근거는 보존하고 늦은 결과는 현재 버전·결정과 대조한 뒤 인수한다. 독립 생성 기능·정책이 허용하지 않으면 가능한 직접 작업은 계속하되 독립 검토 미실시를 밝힌다. 외부 프로세스나 다른 모델로 조용히 우회하지 않는다. 공유 파일 접근의 완전 격리와 도구 수준 권한 강제는 역할 지침만으로 보장되지 않는다.
