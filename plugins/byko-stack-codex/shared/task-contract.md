# 단독 작업의 목적과 범위

이 지침을 쓰는 전문 스킬은 메인과 서브에이전트 어디서든 단독으로 수행할 수 있다. 특정 역할·선행 스킬·호출 양식·문서 세트를 전제로 삼지 않는다. 일반 이슈 전체의 조율은 `byko-work`의 책임이며, 범위가 정해진 전문 작업은 그 경로를 다시 시작하지 않는다.

## 시작과 조사

원래 요청·정정과 적용되는 리포 지침에서 목적·기대 결과·보존 조건·허용 및 제외 범위를 확인한다. 이미 충분히 정한 내용은 재사용한다. 결과를 무엇으로 확인할지 먼저 정하되 분석·조회·단독 리뷰 때문에 전체 설계나 파일 생성을 요구하지 않는다. 새 피드백은 바뀐 부분만 반영하고 기존 유효한 합의를 유지한다.

조사 전에 다음 판단을 위해 확인할 질문과 근거의 공백을 잡는다. 코드와 실제 경로, 구조·컨벤션, 정책·계약, 데이터 자체, 데이터 흐름의 관련성을 먼저 살핀다. 데이터 자체는 값·상태·구조·관계·제약이고, 흐름은 생성·전달·변환·저장·소비·생명주기다. 둘 중 하나를 확인했다고 다른 하나까지 확인한 것으로 처리하지 않는다.

위 관점은 조사 상한이나 모든 도구의 전수 조회 명령이 아니다. 중요한 결론이 의존하는 실제 관계를 확인한다. A의 의미·영향이 B에 달려 있으면 관련 리포·인프라·실행 환경·웹·서드파티 자료로도 이어간다. 문서가 없으면 코드·테스트·설정 등에서 근거를 찾되 관행과 명시된 정책을 구분한다.

**좁은 수행으로 충분하다는 근거를 확인한 뒤 축소한다.** 실제로 확인한 관계·기대값·남은 공백을 근거로 다음 판단이 달라지지 않는지 설명한다. 제목·수정 줄 수·처음 보이는 단순함이나 자료를 아직 안 봤다는 이유로 무관하다고 판단하지 않는다. 필요한 근거가 충분하면 탐색을 마치며 주변 개선으로 범위를 늘리지 않는다.

명시적 제외 범위가 우선이다. 코드 조사만 요청받았다면 DB·로그·외부 서비스로 확대하지 않는다. 범위 밖 연결이 중요하면 그 이유와 현재 답할 수 있는 결과·한계를 반환한다. 조사할 사실을 사용자 선택으로 넘기지 않고, 실제로 남는 의도·정책 선택이나 접근 경계만 특정한다.

## 인계·재개에서 확인할 것

요약·기존 산출물을 길잡이로 사용한다. 맡은 판단에 필요한 원문·목표·현재 대상과 인접 계약을 확인하고, 핵심 전제의 출처·버전·환경이 여전히 맞는지 대조한다. 이전 작업자의 미확인 목록에는 그가 몰랐던 대상이 빠질 수 있다. 목록에 없다는 이유로 연결을 생략하거나 요약에 있다는 이유만으로 확인됐다고 보지 않는다.

현재 경로·소비자·생명주기 등에서 새로 드러난 의존 관계가 맡은 판단을 바꿀지 확인한다. 유효한 이전 조사를 전부 반복하지 않고 새 질문·변경·누락·충돌만 보완한다. 도구·자료가 없으면 가능한 부분은 진행하고 핵심 공백은 미확인으로 남긴다.

## 산출물과 반환

기존에 지정한 자료·형식·위치를 공유하고 갱신한다. 분석의 기본 공유 형식은 Markdown이며 저장 경로·권한이 없으면 응답 자체로 반환한다. 단독 리뷰 보고서는 요청받았을 때만 저장한다. 호출·단계·작업자가 늘어날 때마다 상태 파일과 보고서를 새로 만들지 않는다.

질문의 답 또는 달성한 동작, 기준을 충족한 근거, 확인하지 못한 부분, 필요한 다음 판단을 반환한다. 파일·심볼·라인, 조회 범위·시점, 실행 명령·관찰 결과 등 재확인할 출처를 남긴다. 사실·추론·가정·미확인을 구분하고 도구 로그 전체를 복제하지 않는다. 현재 대상과 다른 버전의 결과를 그대로 통과 근거로 쓰지 않는다.

공유 문서에는 민감한 원문을 불필요하게 옮기지 않는다. 다른 작업자의 변경과 쓰기 소유권을 지키며 스킬 사용을 외부 쓰기·게시·배포·commit의 추가 권한으로 해석하지 않는다.
