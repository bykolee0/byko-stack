# 단독 작업의 목적과 범위

이 지침을 쓰는 스킬은 메인과 서브에이전트 어디서든 단독으로 수행할 수 있다. 특정 에이전트, 선행 스킬, 호출 양식, manifest·spec·progress 파일을 전제로 삼지 않는다. 현재 요청과 사용할 수 있는 자료가 출발점이다.

## 준비와 판단

목적, 기대 결과, 보존할 동작, 허용·제외 범위를 요청과 적용되는 저장소 지침에서 확인한다. 직접 확인할 수 있는 맥락은 조사한다. 이미 주어진 목적과 권한을 재확인 절차로 바꾸지 않는다. 자료끼리 모순되면 확인된 사실과 선택이 필요한 부분을 구분한다.

명시된 범위가 우선이다. 코드 조사만 요청받았다면 DB·로그·외부 서비스까지 확대하지 않는다. 범위가 없으면 목적에 필요한 최소한의 범위를 정하고, 중요한 불확실성이 줄어드는 만큼만 탐색을 확장한다. 결과를 바꾸는 사용자 결정이나 범위 밖 접근이 필요하면 그 이유와 독립적으로 마친 일을 반환한다.

필요한 도구·자료가 없으면 가능한 부분은 진행한다. 누락된 항목을 임의로 채우거나, 핵심 결과를 확인하지 못한 채 완료로 표시하지 않는다. 호출자가 준비하지 않은 문서 세트를 먼저 만들게 하지 않는다.

## 산출물과 반환

기존에 지정한 문서·형식·위치를 따른다. 분석의 기본 공유 형식은 Markdown이며, 저장 경로·권한이 없으면 응답 자체를 재사용 가능한 문서로 만든다. 단독 리뷰는 응답으로 반환하고 보고서는 요청받았을 때만 저장한다. 모든 호출마다 상태 파일이나 보고서 묶음을 생성하지 않는다.

결과에는 질문의 답 또는 달성한 동작, 핵심 근거, 확인하지 못한 부분, 필요한 다음 판단을 담는다. 코드의 파일·심볼·라인, 데이터의 조회 범위·시점, 실행 명령 등 다시 확인할 수 있는 출처를 남긴다. 작업의 성격에 맞게 분량을 정하고 도구 로그를 그대로 복제하지 않는다.

공유 문서에는 민감한 원문을 불필요하게 옮기지 않는다. 다른 작업자의 변경을 보존하고, 스킬 사용을 외부 쓰기·게시·배포·commit의 추가 권한으로 해석하지 않는다.
